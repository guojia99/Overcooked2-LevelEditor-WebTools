Directory: `Assets/commonW3/custom_recipes/salad/models/`.

Each FBX has one mesh, one UV set, one material slot and explicit triangle faces.
No embedded textures, animations, cameras, lights, tangents, rigs or blend shapes are exported.
Both FBX-local vertex arrays and a fresh Blender import are validated: orientation is baked into
mesh data, not dependent on a scene node rotation. Raw FBX local bottom is exactly Y=0.
Blender round-trip bottom differs only by floating-point noise below 0.000001 meter.

For each basename there are three external PNGs and one Unity Standard `.mat`:

- `_Albedo.png`: RGB, 1024x1024, sRGB.
- `_Normal.png`: RGB, 512x512, normal-map importer, linear.
- `_MetallicSmoothness.png`: RGBA, 512x512, linear; R=original metallic, A=1-original roughness.
- Matching `.mat`: built-in Standard shader, white tint, one material slot; three texture references.

Ketchup textures total 1481802 bytes; FBX plus textures total 1693942 bytes.
Mustard textures total 1360979 bytes; FBX plus textures total 1566895 bytes.
Both complete geometry/texture sets are well below 10000000 bytes.
There is no retained 4K extraction, embedded/external duplication, OBJ duplicate or .blend file.
The FBX portable material references albedo only; assign the supplied Unity `.mat` explicitly.

| Asset | GUID | Local ID |

ModelImporter serializedVersion 22 uses legacy `fileIDToRecycleName` entries with the exact
single mesh name (`SaladKetchup` / `SaladMustard`) at 4300000. These are seeded identifiers,
not a claim that Unity itself was run. Confirm after actual Unity 2017 import before writing
serialized Mesh references. Reliable name-based retrieval for the integrating editor factory:

```csharp
// Run in the integrating Unity editor code, which is outside this task's scope.
UnityEngine.Object[] assets = UnityEditor.AssetDatabase.LoadAllAssetsAtPath(modelPath);
UnityEngine.Mesh mesh = null;
foreach (UnityEngine.Object asset in assets)
{
    UnityEngine.Mesh candidate = asset as UnityEngine.Mesh;
    if (candidate != null && candidate.name == modelName)
    {
        mesh = candidate;
        break;
    }
}
if (mesh == null) throw new System.InvalidOperationException(modelPath);
// Assign mesh to MeshFilter.sharedMesh and the supplied .mat to sharedMaterial.
// Saving the prefab lets Unity serialize the actual subasset fileID.
```

Materials are deliberately not auto-created by ModelImporter. Tangents are absent from FBX;
Unity's `tangentImportMode: 3` generates Mikk tangents for the supplied normal maps.
No colliders, secondary UVs, animation, cameras or lights are imported. File units are honored
at globalScale=1. Textures have mipmaps and default compression, with no Read/Write copy.
Folder/model/material/texture meta files use deterministic MD5 GUIDs from the prefix
`salad-sauce:` plus the repository-relative path. Existing meta files are always retained,
including across rebuilds. Asset bundle identity is inherited from commonW3; no new bundle
name is assigned at the model subfolder.

Both meshes keep a uniform scale and real thickness. Horizontal offsets are already baked:
red X/Z=(-0.022,+0.012); yellow X/Z=(+0.022,-0.012). Do not add these twice.
Use local rotation=(0,0,0) and scale=(1,1,1). Relative to the salad surface, red Y=0,
yellow Y=0.006 is recommended when both are shown to reduce coplanar overlap.
The small Y offset is integration data, not baked, so both individual bottoms remain Y=0.
Raise their common parent to the actual salad surface; plate AttachPoint is only a baseline.

The original official plate prefab is in bundle47. Its Plate child references
`bundle39:m_sk_plate_02` (pathID -7177850975923356518). Mesh diameter is 0.997930 meter,
child scale is 1, rotation is identity; official food AttachPoint Y is 0.08433009 meter.
The requested 0.65-meter sauce span was chosen against these real measurements.
Angles are the measured XZ PCA major axis from +X toward +Z modulo 180, not node Euler values.

## Reproduction And Checks

Run from the repository root:

```sh
python3 layout-editor/scripts/prepare-salad-sauce-models.py --plate-reference
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python-exit-code 1 --python layout-editor/scripts/prepare-salad-sauce-models.py -- --build
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python-exit-code 1 --python layout-editor/scripts/prepare-salad-sauce-models.py -- --verify
```

`--build` uses system `python3` plus UnityPy for read-only plate measurements, then Blender's
bundled numpy for PCA, uniform transforms, UV-preserving collapse and texture processing.
Override relocated sources using `--source-dir`. Keep the recorded Blender version for
repeatable decimation; FBX export timestamps can change file hashes across otherwise identical builds.
`--verify` runs in a separate Blender process, checks source/texture hashes and GUIDs, imports each FBX
into an empty scene, parses the raw FBX geometry and writes `independent-validation.json`.
It checks face counts, UV finiteness, material slots, local/world bounds, angles, footprint
radius, image resolution/path availability, no animation, no embedded data and no tangents.

`report.json` additionally records sampled source-to-reduced surface errors and outer-footprint
support errors over 180 directions. These are one-way sampled geometric checks, not a full
bidirectional Hausdorff or visual-quality proof. Uniform geometry transforms preserve source
UV handedness; no remeshing or UV regeneration is used.
