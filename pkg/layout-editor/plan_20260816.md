## 三、待开发项明细

### 3.1 E3 自定义菜单任意烹饪步骤组合（❌）

**现状**：
- web 自定义菜谱编辑（`customRecipes.ts`）每个菜谱只有单个 `cookingStepId`（外加 `Composite` 类型的子菜谱组装）。
- `Assets/Scripts/LevelEditorStub/CustomRecipeSO.cs` 镜像里也只有单个 `cookingStepSO`（+`cookingStepIconSO`）字段。
- 插件 DTO `LayoutCustomRecipeDto` 同样单步骤。

**待确认问题**：
- mod 新版 CustomRecipeSO 的步骤组合字段名与结构是什么？（数组？`cookingSteps[]`？每步是否带独立图标/进度参数？）
- 与既有 `cookingStepSO` 单字段的兼容关系（旧菜谱如何迁移）？
- 步骤组合与 `CookingProgress`/`MixingProgress` 的关系？

**修改意见**：
1. 拿到 mod 新字段定义后，先在插件 DTO（`LayoutEditorModels.cs`）加 `cookingStepGuids: string[]`（保序），读写走反射（不能改 stub）。
2. web 自定义菜谱编辑页把单选下拉改为"步骤序列"编辑器（可增删、拖拽排序），UI 可复用现有 `cooking-steps.json` 图标。
3. 菜谱卡片分组推导（`recipeGroups.ts` / `build-catalog.mjs` / `LayoutEditorRecipeKnowledge.cs` 三处镜像逻辑）需要支持"多步骤序列"：每步一组，组顺序=步骤顺序。
4. 注意保持三处镜像算法一致（已有教训：月亮派半成品分支就是三处同步加的）。

### 3.2 E4 自定义厨具中的食材模型（❌）

**现状**：
- web 自定义菜谱已支持**成品模型**上传（fbx/obj + 贴图，`customRecipes.ts` 的 `reusableModels` 链路）。
- "厨具中的食材模型"（如自定义食材在锅里的展示模型）是 utensil/ingredient 层面的新配置，插件 DTO 与 web UI 均无。

**待确认问题**：
- mod 侧该配置挂在哪个类上？（CustomRecipeSO？CustomIngredient？还是新的 SO？）字段结构（每烹饪步骤一个模型？）？
- 模型文件格式/导入路径约定是否与成品模型一致（obj/mtl/贴图重命名管线可直接复用吗）？

**修改意见**：
1. 优先复用现有模型上传管线（`fbxTextureRename.ts` / `mtlTextureRename.ts`）。
2. UI 位置建议放在自定义菜谱编辑页的"步骤"区域（若按步骤配模型）或食材编辑区（若按食材配）。

### 3.3 E5 一个厨具匹配多种烹饪台（❌）

**现状**：
- `PseudoPrefabCookingUtensilStub.allowedCookingStationTypes: CookingStationType[]` 字段已存在于 stub 镜像（mod 数据结构就绪）。
- 插件 DTO `LayoutCookingUtensilStubDto` **不携带**该字段；`LayoutEditorStubIO` 的 Export/Apply 不读写；web 厨具参数面板（`stubControls.ts` CookingUtensil case）只有容量+额外食材。

**修改意见**（链路最短，仅次于 E6）：
1. `LayoutCookingUtensilStubDto` 加 `stationTypes: string[]`（枚举名数组，避免 int 语义漂移）。
2. `LayoutEditorStubIO` Export/ApplyStub 的 CookingUtensil 分支读写该字段（enum 名 ↔ 字符串转换，C#6 语法）。
3. web `stubControls.ts` 厨具面板加多选（复用分类弹窗或 checkbox 组），选项来自 `CookingStationType` 枚举（需确认完整枚举值清单）。
4. 空数组的语义需确认：是"匹配所有烹饪台"还是"不匹配任何"——按 mod 行为对齐。

### 3.4 E6 关卡最小/最大菜单数目（⚠️ 后端已通，只差前端）

**现状**：
- 后端已完成：`LevelConfigUpdateDto.minOrderCount/maxOrderCount`（`LayoutEditorModels.cs` L941-942/966-967），`LayoutEditorLevelAdminApi` 读写带 Clamp（L406-407、L773-776，含 min>max 自动纠正）。
- web 的关卡配置 UI（`levels.ts` 分数配置弹窗 / `/api/level/config` 调用处）**没有这两个输入框**。

**修改意见**（建议最先做）：
1. `levels.ts` 关卡配置弹窗加"最少/最多菜单数"两个 number 输入（范围参考 Clamp 逻辑：1~?，需确认 ClampOrderCount 上限）。
2. `types.ts` 的 LevelConfig 相关 interface 补 `minOrderCount/maxOrderCount` 字段。
3. 校验：前端提交前做 min≤max 提示（后端已兜底）。

### 3.5 E7 关卡默认厨师帽样式（❌）

**现状**：
- `LevelInfoSO` stub 镜像中**没有** hat 相关字段（只有 `PseudoPrefabPlayerStub.hatVisState`，是可见性不是样式）。
- 该字段应为 mod 新版 LevelInfoSO 新增。

**待确认问题**：
- 字段名与类型（枚举？int index？SO 引用？）？可选样式清单从哪来（游戏内置帽子列表是否可枚举）？

**修改意见**：
1. 字段在宿主类上 → 插件侧用**反射**读写（铁律：不改 `Assets/Scripts/`），写入前 `GetField` 判空防御（旧版 mod 无此字段时不报错）。
2. web 关卡配置弹窗加下拉（样式清单需后端枚举下发，放进 `/api/level` detail 或新端点）。
3. 与 E6 共用同一个配置弹窗，一次做完。
