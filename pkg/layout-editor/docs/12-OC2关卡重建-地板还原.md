# 12 · OC2 关卡重建：地板还原（baked ground）

> 管线：`layout-editor/scripts/oc2-rebuild/`；核心模块 `oc2r/bakedfloor.py`。
> 目标：让 oc2_story / oc2_horde / oc2_dlc_story 的生成场景出现与原始关卡一致的地面（材质、拼块、位置、旋转），取代旧的“单张兜底 Plane + 设计期 `mat_old_tiles` 方砖”。

## 1. 为什么原来的地板是错的

- OC1 关卡（`Assets/LevelSets/oc1_story`）把地板作为逐格 tile 摆进场景，可以直接导出；
  OC2 不同：厨房地面被**烘焙进组合网格**（`Design/Lightmap_*_Baker/CombinedMesh-*-mesh`），
  或者以静态合批（`m_StaticBatchInfo`）的形式挂在 `Combined Floor Tile` 之类的对象上，
  部分关卡还有 `Design/Floors` 下的独立 quad（工程 Mesh 资产），少数关卡完全没有地面（运行时生成或用 prefab 地板）。
- 旧管线只收内置 `Plane(10209)`/`Quad(10210)` 的 plain GameObject，因此：
  - 主体地面收不到 → 只剩一张 `FLOOR_MAT_GUID` 兜底大平面；
  - `Design/Floors/Tiles/Kitchen_Tile_*` 这类设计期 `mat_old_tiles` 方砖被当成可见地板输出 → 出现用户截图中的深蓝灰大砖/错位观感；
  - `matcher.BAKED_NAME_RE` 还会把 `Combined Floor Tile` 整棵跳过。

## 2. 抽取规则（`bakedfloor.collect`）

按优先级收集，同一几何按 `(mesh_rel, submesh_index, 节点路径)` 去重：

1. **烘焙合并网格**：路径含 `mesh_baker/mesh_bakers/combinedmesh/lightmap_` 且 `m_StaticBatchInfo.subMeshCount==0` 的 `-mesh` 节点，整张网格逐子网格取；顶点是世界坐标，**不再叠节点 TRS**。排除 `not_lightbaked`（备份层）。
2. **显式地板对象**：名字或路径含 `floor` 且 `m_StaticBatchInfo.subMeshCount>0`，按 `firstSubMesh/subMeshCount` 取批内子网格（世界坐标）。
   少数未合批的独立 quad（mesh 资产名以 `Quad*`/`Plane*` 开头，如 balloon 篮底）按局部坐标 + 节点 TRS 取。
3. **`Design/Floors` 下的独立四边形**（`Mesh/Quad_29.asset` 等）：局部坐标 + 节点变换。
4. **`Art/Scenery`、`Art/Decoration`、`Art/Ground` 下的整块地面**：材质名匹配 `_GROUND_MAT_RE`（floor/tile/path/road/pavement/plank/grass/sand/stone/…）的平网格。
5. 兜底：若以上都没有，`extract` 保留旧的内置 quad 地板通道；再没有才铺兜底 Plane。

过滤与清洗：

- 解码后按**真实顶点包围盒**判平面（`_flat_box`：y 跨度 ≤ 0.25、中心 y ∈ [-0.8, 0.8]、xz 面积 ≥ 1.5）；AssetRipper 的 `m_LocalAABB` 对复用 Quad 常是 1×1，不可作判据。
- 材质黑名单 `_NON_FLOOR_RE`：桌椅/台面/货架/开关/灯笼/遮阳伞等非地面物件。
- 软地表抑制：草/泥/水/沙/雪的中心落在石/砖/木板/道路范围内时丢弃（避免泥地盖石板）。
- 同材质、中心相距 < 0.5m 的重复候选去重（静态合批 mesh 被多节点复用）。

## 3. 网格与材质

- 每关生成**一个**合并地面网格：`Assets/LevelSets/<set>/meshes/<scene>_ground.asset`，
  guid `md5("oc2rebuild:mesh:<set>/<scene>/ground")`，meta 为 `NativeFormatImporter mainObjectFileID 4300000`。
- 顶点通道（Unity 2017）：`m_CurrentChannels = 11`（position|normal|uv0），uv0 必须是 `m_Channels` 的 **index 3**（data offset 24）；写错成 uv1 时 Unity 里 uv 全 0、地板无纹理。
- UV：
  - 材质带 `_WorldUVMultipllier`/`_WorldUVRotator` → 按世界坐标烘焙 UV（`_WorldUVRotator` 是**角度**）；
  - 否则用网格自带 uv0；
  - uv0 全 0 时退回材质主贴图 scale 兜底。
- 材质走 `floormats.ensure_baked`：复制贴图到 `Assets/commonW1/textures/oc2rebuild/`，
  材质写到 `Assets/commonW1/materials/oc2rebuild/`，shader 统一为内置 **Standard（fileID 46）**，
  `_DiffuseMap/_Albedo/_BaseMap/_BaseColorMap` 改名 `_MainTex`，`_MainTex` scale/offset 置 1/0。
- 同名材质/贴图来自不同 DLC 目录时，文件名追加 `__<guid 前 8 位>`，避免互相覆盖导致场景丢 guid。

## 4. 场景输出（emit）

- `Floor` GameObject 挂在 `Art/Ground` 下，单位变换；`MeshFilter` 引用工程 Mesh：
  `m_Mesh: {fileID: 4300000, guid: <mesh guid>, type: 2}`，`MeshRenderer` 材质数组按子网格顺序。
- 存在 baked ground 时：
  - 不再输出兜底 `Floor` Plane；
  - 不再输出 `Design/Floors` 的设计期地砖（`Kitchen_Tile_`、材质含 `old_tiles` 的 `_add_floor` 直接跳过）。
- 没有 baked ground 但场景里已有 prefab 地板（名字/容器含 floor/ground/raft/plank）时，`has_floor_item=True`，同样不铺兜底平面。

## 5. 校验

- `rebuild.py` 每关生成后 `verify.verify` 反解比对，mismatch > 0 即失败；
  `validate_sets.py` 再做引用闭合/guid 存在自检。
- 视觉对照：`/tmp/render_floor.py`（离线正交俯视光栅化）用来对比 `data/<id>/screenshot.png`；
  Unity batchmode 里 Standard shader 没有 vertex shader pass（`WARNING: Shader Unsupported ... All passes removed`），
  只能验证导入/引用，不能当视觉依据。
- 当前基线：140 关（45 + 8 + 87）全量重建 0 失败；127 关引用 baked ground mesh，
  3 关用内置 Plane（Story_07/17 是筏子地板，DLC11_1_2 为兜底），其余依赖 prefab 地板。

## 6. 已知遗留

- 角色/NPC rig（`Art/NPCs`）按“不要 T-pose”策略被 matcher 跳过；它们需要在运行时由 bundle prefab 还原，暂未纳入场景。
- DLC02 沙滩主地面、DLC11_1_2 浮台地面等运行时生成/无场景几何的关卡，仍可能只剩兜底或 prefab 地板。
- `Worktop/Mesh` 之类的场景内嵌子网格被丢弃属于预期（父 prefab 已含同网格）。

## 7. 打开场景时的 Timeline 断言（已知，未改代码）

- 症状：打开 `s_oc2_story_00_tutorial` 等含 Timeline 的场景，Console 出现 6 条
  `Assertion failed on expression: 'pred(*previous, *i)'`，堆栈
  `UnityEngine.Object:Instantiate` → `PseudoPrefab:ResetChild()`。
- 原因：Unity 2017 的原生缺陷——从 AssetBundle 克隆含多个 `PlayableDirector` 的 prefab
  （`Timeline_Tutorial_01` 6 个、`Timeline_DynamicStage_04` 15 个）时，
  `remove_duplicates.h` 的排序断言被触发；与场景数据无关，也不影响运行。
- 处理：**不改代码**。编辑模式占位会导致 Timeline 不在编辑器内播放，因此保留现状；
  断言只在编辑器 Console 出现，打包/运行时不受影响。
