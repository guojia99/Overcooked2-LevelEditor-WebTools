# 原生模式接口

本页对应 stdio MCP 的 `layout-editor/mcp/src/level-mode.ts`、`level-settings.ts` 与原生 HTTP `/api/mcp` 的实现；清单位于 `layout-editor/mcp/tool-manifest.json`，Schema 为 `level-mode.schema.json`、`level-settings.schema.json`。stdio 通过 `BridgeClient` 调用 REST；HTTP MCP 直接调用相同 Admin 服务方法。在线能力以 `/api/mcp/tools` 或 `tools/list` 为准，源码注册不代表运行中的 Unity 已重编译。

## 工具与调用

| 工具 | arguments | REST | 副作用 / 读回 |
|---|---|---|---|
| `oc2_get_level_mode_config` | `{assetPath}` | `GET /api/level/mode-config?assetPath=` | 只读 DTO，含敌人目录 |
| `oc2_save_level_mode_config` | `{config:LevelModeConfigDto,confirm:true}` | `POST /api/level/mode-config`，body 为 config 去掉只读 enemies | `write_asset`，同步 sidecar 和本关专属 SO；自动 GET 同一路径并比较 |
| `oc2_change_level_mode` | `{assetPath,gameMode,convertHordeObjects?,confirm:true}` | `POST /api/level/mode`，body `{assetPath,gameMode,convertHordeObjects}` | `write_scene`，切换原生控制器/绑定，可显式授权原子转换交付窗；自动 GET 模式及详情 |
| `oc2_create_level` | `{setName,levelId,levelName?,levelNameZH?,gameMode?,confirm:true}` | `POST /api/level/create`，不传 confirm | `write_scene`，默认 Campaign；从关卡列表解析实际资产路径后 GET 模式及详情 |
| `oc2_save_level_respawn_bounds` | `{assetPath,enableRespawnBounds:boolean,confirm:true}` | GET 详情 → `POST /api/level/info` → GET 详情 | `write_asset`；合并完整旧基础标量，显式更新并核对布尔值 |
| `oc2_save_native_scripted_recipes` | `{assetPath,playerCount:1..4,scriptedRecipes:GUID[],confirm:true}` | GET 详情 → `POST /api/level/config` → GET 详情 | `write_asset`；仅 Campaign，合并指定人数标量，仅提交该人数，核对序列及诊断 |

`assetPath` 一律是列表/详情返回的 **LevelInfoSO .asset 路径**，不是 `.unity`。场景布局仍使用单独的 `sceneAssetPath`。创建的 setName/levelId 只允许小写字母、数字、下划线；新建后以列表实际返回的路径为准，不由客户端猜 SO 文件名。

创建接口参数不变：后端按所选 campaign/dynamic/horde 目录预检并完整复制私有 YAML 资产，重映射 LevelInfo、config、材质、controller/clip 的内部引用，保留公共依赖及模板默认菜谱/阶段/波次。Dynamic 源 levelinfo 的人数引用错配只在副本计划中修正。新场景打开前完成绑定与模式 store 初始化；非场景资产清空显式 bundle 标签继承集 info，Horde 被替代的本次中间配置会清理。缺模板/缺引用在复制前拒绝；后续失败恢复登记并删除新路径，清理失败会明确列出残留。仍按下文 `WRITE_UNCONFIRMED` 恢复契约先查列表，不自动重试。离线复制/事务测试不增加 MCP `verified:true` 的保证范围，也不替代真实 Unity 验收。

`gameMode` 大小写固定为 `Campaign | Dynamic | Horde`。读取支持三种模式；保存配置只支持当前已经生效的 Dynamic/Horde，不能借配置保存切换原生模式。Campaign 菜谱沿用原有菜谱 API。先 GET，修改完整 DTO，再保存；没有 PATCH 语义，遗漏字段不能理解为保留。

## LevelModeConfigDto

重生边界和原生序列详见[原生序列与重生边界契约](../native-scripted-recipes-contract.md)。详情路由为 `GET /api/level?assetPath=`。`configs[0..3]` 保序回显 1P–4P 原生 `scriptedRecipes`，保留重复和坏引用位置（缺 GUID 为 `""`），`scriptedRecipeErrors` 是只读位置诊断；Dynamic/Horde 也回显休眠序列。MCP 不隐式删除坏位置。保存工具只接收显式 GUID 数组，`[]` 为明确清空，缺省/null 拒绝。底层 REST `/config` 的缺省/null 仍为保留，其他模式不得回传非 null 数组。

两项最小保存工具先读取最新详情，respawn 合并基础标量、网格及依赖，原生序列合并该人数现有时长、分数、存活倍率和只读修复费用原值；用户无需填写这些标量。`exists`/诊断不作为 stdio 可写参数传入，其他人数不发送。后端统一验证引用、配置所有权以及 Web OrderSequence 互斥，失败不自动清除任意序列。保存成功后再次读详情，原生序列核对指定人数存在、Campaign、长度、顺序、重复、GUID 身份（大小写不敏感）和零引用诊断。所有工具拒绝未知顶层参数，boolean 不接受字符串/数字，人数必须为 1–4 整数。

| 字段 | 契约 |
|---|---|
| `assetPath`, `gameMode` | 本关 LevelInfoSO 路径、当前原生模式 |
| `phases[]` | Dynamic 专用，2–64 个 `{id,durationSeconds,recipeGuids}`，按运行顺序排列 |
| `hordeConfigs[4]` | Horde 专用，数组下标 0–3 固定对应 1P–4P，每项 `{targetRepairCostMax,waves[]}` |
| `waves[]` | 1–128 波，每波 `{id,intervalSeconds,recipeGuids,enemyGuids,spawnTimes}` |
| `targetHealth`, `kitchenHealth` | 整数 1–1000000 |
| `targetRepairSpeed`, `targetRepairThreshold` | 有限数 0–1000000；原生存储 float，读回容许 float32 往返及 Unity JSON 有效位精度 |
| `minOrderCount`, `maxOrderCount` | 整数，`1 <= minOrderCount <= maxOrderCount <= 10` |
| `enemies[]` | 只读目录，至多六项 `{guid,id,nameZh,nameEn,assetPath}`；nameEn 可能为空/null，后端可能带 group 等附加目录字段；MCP 保存时移除整份目录 |

阶段和同一人数配置内的波次 ID 必须非空、无控制字符、唯一且不超过 128 字符。阶段时长为 1–86400 整数秒；波次间隔与每项 spawnTime 为 0–86400 整数秒。每份菜单 1–256 个真实菜谱 GUID，每波 1–256 个敌人 GUID。`enemyGuids` 与 `spawnTimes` 必须等长，按下标逐项对应；**允许重复同种敌人及同一时间生成，不能去重或分别排序**。每份配置中菜谱与敌人总条目数不超过 32768。非当前模式数组使用 null/空数组，不能混用两个模式的数据。

敌人仅允许 `Assets/common04/game_environment/horde/enemies/` 下六个 SO：`horde_biscuit_a`、`horde_candy_b`、`horde_puddin_c`、`unbread_a`、`unbread_b`、`unbread_c`。GUID 必须从 GET 目录选择；普通食材目录或其他 common 库中的同名物件不构成有效敌人。MCP 检查结构、GUID 格式及限额；真实菜谱/敌人解析、路径和资产归属校验仍由后端负责。

POST 编码后的 UTF-8 JSON 不超过 **2097152 字节（2 MiB）**，后端还限制实际格式化 sidecar 的字节数。保存位置为 `data/<level>/mode_config~/mode_config.json`，此 `~` 目录不进 Unity bundle。运行时依赖同步到本关 `mode_assets/r_<revision>/` 下的专属 RecipeListSO / HordeLevelConfigSO / HordeWaveDataSO / 人数配置，不能就地修改 common 模板或其他关卡共享 SO。编辑器 ID 由 sidecar 保存；运行时读原生 SO 图。GET 为只读，不能把一次 GET 当成迁移或保存。

## 原生模式与 Web 分 P

Web `partLevel` 是独立的布局阶段系统（`part_level~/part_level.json`）；原生 Dynamic 使用 `recipeListSOs`、`roundTimes` 和 `DynamicFlowController`，Horde 使用四份人数配置及波次。不能把 `partLevel.parts` 转成原生菜单阶段，也不能把 Web transition 当作原生 Dynamic transition。

切换由后端原生事务执行，要求目标场景已打开并激活、所有已打开场景干净，关联 LevelInfo/人数配置已保存，且有唯一、有效绑定的 Manager/FlowManager/Debugger。编译、导入、Play 切换或导出时拒绝；其他伪预制体场景需先关闭。客户端不要为规避守卫自动保存脏场景或强制重建 Manager。

`convertHordeObjects` 是可选的精确布尔值，默认 false；stdio 省略时明确发送 false，不接受字符串或数字。只有用户明确同意交付窗转换后才可传 true；`confirm:true` 仍为必填，单独确认切换模式不等于授权自动开启此选项，失败重试也不能自行改为 true。

设为 true 时，后端在同一原生切换事务内双向转换**已支持的普通 ServingStation wrapper 与 Horde Service_Window wrapper**。原 GameObject、位置、名称和回收绑定保留，外观与组件改变；不支持的物件仍按后端守卫处理，不能假定任意原生 PlateStation/HordeTarget 都可转换。false 时不转换，目标模式的交付口守卫照常执行。进入 Horde 的最终场景需至少一个激活的有效 Horde 交付窗且无普通交付口。

**切出 Horde 不要预删最后一个 Horde 窗**：Horde 场景本身要求有交付窗，先删最后窗再写回会形成旧流程死锁。保留受支持的窗，在用户同意后传 `convertHordeObjects:true`，由事务将其转为普通交付口。金币解锁 gate 不自动转换，切出前须先删除 gate 并保存；正常 Horde 允许没有金币 gate。门具 stub 字段见[场景接口](05-场景编辑接口.md#horde-门具-stub)。切换后另 GET 场景布局核对转换后的类型、外观、原 GO/位置/名称和回收绑定；模式/详情读回不替代物件转换验收。

进入 Dynamic 需要 N 个菜单阶段对应 **N−1 个已有、有效的原生 AnimatedDynamicTransition**，位于 Manager 的 FlowManager 下。每个转场物件恰好一个原生转场组件，本场景 Animator/controller/trigger 有效，Animator 含对应 Trigger 参数和 `IsTransitioning` Bool 参数。不能复制引用模板地形的转场、伪造空转场，也不能从 Web 动画组推断转场。修改配置阶段数后仍须核对本场景原生转场数。

当 Web `partLevel.enabled=true`，后端拒绝切到 Dynamic/Horde。现有 Web 分 P 保存后不可直接关闭；需要独立的原生模式关卡时应新建目标模式关卡，或使用既有历史恢复流程。MCP 不代改分 P sidecar。

## 结果、超时与恢复

保存成功 data 为 `{saved,readback,verified:true}`；切换和创建另返回 `detail`。HTTP MCP 的 `structuredContent` 直接包含此对象，stdio 包在统一结果的 `data` 内。`verified:true` 表示读回值匹配：保存对照全部可写字段（排除 enemies，非当前模式数组规范为 null；仅两项修复 float 参数允许 float32 往返及 JSON 七位有效数字误差，相对容差 1e-6，绝对下限为最小 float32 次正规数），切换/创建核对模式与 LevelInfo 路径。它**不证明**场景重新从磁盘打开后的组件图、Unity Play、导出或真机行为已经通过。

stdio GET 每次 30 秒上限，POST 每次 60 秒上限；一次创建最多 POST + 列表 GET + 模式 GET + 详情 GET。HTTP MCP 在 Unity 主线程同步执行服务调用与读回，不经过 REST 网络请求；整次模式写调用建议 180 秒客户端超时。写操作同步等待，无任务 ID、无写操作状态轮询；中断/超时不代表 Unity 取消，MCP 内部不会自动重试。

| 错误 | writeOutcome | 恢复 |
|---|---|---|
| `INVALID_ARGUMENT` | `not_started` | 本地校验失败，没有 POST；修正参数 |
| `BRIDGE_ERROR` | `not_started` | 重生边界/原生序列保存前详情 GET 失败；只读核对后再决定 |
| `WRITE_UNCONFIRMED` | `unknown` | POST 报错、连接中断或未确认 ok=true；先查健康，再 GET 模式/详情；创建先查列表 |
| `READBACK_FAILED` | `acknowledged` | POST 已确认，但读回报错/不匹配；只重做 GET，不再次 POST |

所有写错误 `retryable:false`，保留实际副作用 `write_asset/write_scene`。只读恢复后核对现状及写回历史，确定是否需要后续修改；不要因断线重放创建、切换或保存。

## 原生 HTTP MCP

`LayoutEditorMcpApi.ToolsJson()` 注册四工具，`LayoutEditorHttpServer.HandleMcpTool()` 分派，`McpArgumentsDto` 承载完整参数。JSON-RPC `method` 仍是 **tools/call**：

| params.name | params.arguments | 服务方法 |
|---|---|---|
| `oc2_get_level_mode_config` | `{assetPath}` | GET 同名 REST / `GetLevelModeConfig(assetPath)` |
| `oc2_save_level_mode_config` | `{config,confirm:true}` | POST config DTO / `UpdateLevelModeConfig(config.assetPath,config)`，须保持 2 MiB、历史、安全检查及读回比较 |
| `oc2_change_level_mode` | `{assetPath,gameMode,convertHordeObjects?,confirm:true}` | POST `{assetPath,gameMode,convertHordeObjects?}` / `ChangeLevelMode(LevelModeChangeDto)`，之后读模式+详情 |
| `oc2_create_level` | `{setName,levelId,levelName?,levelNameZH?,gameMode?,confirm:true}` | POST `LevelCreateDto`（默认 Campaign），列表解析路径，读模式+详情 |

`McpArgumentsDto` 包含 `LevelModeConfigDto config` 和 `string gameMode,levelId,levelName,levelNameZH`。HTTP MCP 在读取请求流时限制 envelope 为 **8 MiB**（包括 chunked body），再在完整 RPC DTO 反序列化前检查原始 config 的 **2 MiB** UTF-8 大小；调用 `ParseJson`，拒绝未知/遗漏的可写字段及错误数字类型，避免 JsonUtility 静默丢弃配置。后端仍校验格式化 sidecar 的 2 MiB 限额。现有大文档 scene commit 不使用模式配置的 2 MiB 限额。

内置 RPC 的原始参数白名单已包含 `convertHordeObjects`，仅接受 JSON true/false，缺省仍为 false；不再误按字符串校验。新增两项保存工具使用 HTTP 文件内的局部参数 DTO，原始参数先校验未知键、必填字段及精确类型，再进入 JsonUtility；不扩写 Admin/Models。stdio 使用同样参数规则和错误分类。

保存调用 `BeginForInfo("level-mode-config", path)` → `UpdateLevelModeConfig` → `CommitNow()`；错误或异常执行 `Abort()`，不把历史清理理解成资产回滚。确认写成功后独立读取配置并比较；读回失败保留已提交历史，返回 `READBACK_FAILED/acknowledged`。三种写错误通过 `isError:true`、`structuredContent.error`、`data.writeOutcome` 和实际 `operation.sideEffect` 返回，均为 `retryable:false`。本地清单已移除四工具的 `stdioOnly` 标记；运行中的 Unity 仍需重新编译后探测在线注册。
