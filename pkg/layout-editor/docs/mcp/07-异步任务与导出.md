# 异步任务与导出

## 导出

`oc2_start_export` 不等待构建完成，立即返回 MCP `taskId`、轮询间隔和最大等待时间。必须传 `confirm: true`。

推荐调用：

```text
oc2_start_export(setNames=["<set>"], mode="levels", confirm=true)
  -> taskId
  oc2_wait_export(timeoutMs=1800000) // 仅 stdio MCP
  -> done/error
oc2_get_export_status()
```

当前 Unity Bridge 导出状态是全局状态，底层以关卡集名作为状态标识。因此同一时间不要并发启动多个导出任务。

`setNames` 为非空数组，`mode` 为 `all`（默认）、`levels` 或 `deps`；可选 `depsVersion` 和 `selectedLevels` 会透传给 Bridge。`taskId` 是 MCP 返回的关联标识，不是后端独立任务队列；应同时核对状态中的集名（多集以 `+` 连接）、模式和结果，不能只凭旧的 `done` 判定本次任务完成。

## 导出模式与构建范围

| 模式 | 交付根和内容（build map 另扩展共享归属） | Runtime 编译闸口 | BeforeBuild staging |
|---|---|---|---|
| `all` | 本次关卡集和一份依赖包 | 执行 | 执行 |
| `levels` | 仅本次关卡集，另需匹配依赖包 | **仍执行** | **跳过** |
| `deps` | 仅 commonW、统一运行时及非基础依赖闭包，不遍历关卡场景 | 执行 | 执行 |

正常 levels/all/deps 均保留输出 bundle、`.manifest` 与 `.meta`。`CollectBuildOwnership` 把本次根可达的共享 base/commonW 包加入显式 build map，配合 `BuildAssetBundleOptions.None` 增量构建，确保资产归属；这些共享包可能参与构建，不能承诺完全不处理 common，也不是无脑全库构建。`_builtBundleNames` 只保存交付根。levels 的“不 staging”仅指不调用 BeforeBuild；编译/域重载的生命周期回调仍可能 staging。

导出会自动执行空可选包预检（`phase=preflight`），无需新增参数或手动先调用其他工具。它与导出前 `deps-manifest` 的计划展示不同，也不代表后续实际构建与交付验证已经完成。

`selectedLevels` 为单集场景名列表（`LevelInfoSO.sceneName`），省略/空/全选按整集处理；多集带选择报错，deps 忽略选择。只准备/构建入选场景，暂时过滤 `levelInfos` 后构建部分集 info，结束时恢复并保留异常恢复机制。未选纯场景包和旧目录残留不进入本次交付。

打包以**本次构建 manifest 和已验证列表**为准，文件缺失、未在本次 manifest 中或非基础依赖闭包不完整均失败，不能用旧产物代替。依赖闭包按拓扑序包含 hash 等传递依赖；基础 `common` / `common01`–`common04` 及其子包由预装前置提供，不随包。新依赖包写 `bundle_dependencies.txt`，逐行列出拓扑顺序的依赖文件名，不含单独优先加载的统一运行时；数字 `commonwN` 交付为 `commonWN`，其他文件名保留。

Prepare 后特征收集除 tag/组件/名字外还读取持久 Stub/SO 的 `prefabName`，补齐被移除预览 child 或改名伪根上的 terminal/hotpot/pushable 特征。Runtime 的 `DirtyTeacup|` 自愈补挂 watcher，缺字段时仅从唯一可靠的已加载原生脏茶杯堆资产恢复模板；仍需 Play/真机确认。

终端持久扫描块要求 Stub/SO 非空：typed `PseudoPrefabTerminalStub` 独立确认终端身份，或 SO 名含 `ControlTerminal` 且排除 `_Marker`，同时确认未绑定才标 `terminal`。茶杯 `Start` 缺模板时最多尝试 10 次，间隔 1 秒、最多 9 次等待；最终失败一次告警并 `yield break`，不进入合并轮询。

导出前 `GET /api/set/export/deps-manifest` 的 `BuildDepsManifest` 现在列出 hash 等非数字依赖和 `bundle_dependencies.txt`，计划失败时 `ok=false`。预检展示的是计划与已有产物参考大小，不代表已经构建或验证实际 Runtime 内容。

## 兼容方向与发布号

新版 Loader 支持所有带有效 `stub_levels.txt` 的旧集，至少覆盖 3.10.x，并执行 `requires.txt` 数字段版本门控；无清单不支持，也不生成 legacy 通配条目。**这不是新导出支持旧 3.10 Loader/Runtime。** `requires.txt` 缺失但有合法清单时告警兼容；非法、不可读或要求版本过高时跳过该集。

`bundle_dependencies.txt` 属于**依赖包**，不是逐关卡清单。旧 3.10 依赖包缺此文件时，新 Loader 继续按历史数字规则发现 commonW/common0N；新清单存在但非法/缺文件/不可读时整份拒绝并告警，不回退扫描。获准的空 `stub_levels.txt` 也激活依赖加载，无清单集则不支持。

本次未修改发布号。`depsVersion` 是用户指定的包标识，不替代 Runtime/Loader 发布版本和 `requires.txt` 门控；同号文件仍可能更新，需核对实际构建来源和 MD5。

`requires.txt` 门控比较 Loader 发布版本，不能替代实际加载 Runtime 的内容/版本核验。外部预载同名程序集仍可能有类型身份冲突；bundle 的已加载判断按内部名，不能证明字节相同。这些已知限制尚未完全解决，不能从预检或离线通过推断消除。

## 时间和轮询

- 普通读取：直接等待，最大 30 秒。
- 场景写回：直接等待，建议最大 120 秒。
- AssetBundle 导出：每 2 秒轮询，最大 30 分钟。
- Unity 域重载：连接暂时返回 HTML 或连接失败属于可恢复状态，应先等待 3 秒再调用健康检查。

原生 HTTP MCP 不在 Unity 主线程内同步阻塞等待，应由 HTTP 客户端每 2 秒调用 `oc2_get_export_status`；`oc2_wait_export` 只由 stdio MCP Server 在其进程内提供。

### 状态快照与固定阶段行

`GET /api/set/export/status` 与 `oc2_get_export_status` 返回同一 `SetExportStatusDto`。stdio MCP 原样透传后端快照，不生成进度。顶层保留 `status`（`idle|running|done|error`）、`setName`、`phase`、`message`、`error`、`zipFileName`、`fileCount`，新增字段如下；没有新增工具、请求参数或版本号：

| 字段 | 契约 |
|---|---|
| `mode` | 本次实际规范化后的 `all|levels|deps` |
| `stages[]` | 固定行序的阶段快照，每行独立保存状态、耗时、计数和消息 |
| `stages[].phase` | 下表中的固定阶段标识 |
| `stages[].state` | `waiting|running|done|error|skipped`；未开始、执行中、完成、失败、不适用/未执行 |
| `stages[].elapsedMs` | 后端累计毫秒数；运行行包含当前已消耗时间，前端不自行外推 |
| `stages[].completed` / `total` | 已完成数 / 总数；`total=0` 表示不可计数，不是零工作量或完成 |
| `stages[].message` | 该行实际后端消息；与顶层当前消息分开保存 |

固定行序为 `queued → starting → compile → preflight → orphan-clean → dual-stub-clean → prepare → build → package → zip → restore`。每行状态由快照决定，不能按数组位置推断前面都已完成；`clean` 不属于新契约的固定行，`done/error` 是顶层终态，不追加为阶段行。

| phase | 含义 |
|---|---|
| `queued` | 等待 Unity 编辑器执行任务 |
| `starting` | Unity 的 delayCall 已执行，开始启动导出 |
| `compile` | 等待统一运行时编译及域重载，完成后自动续跑 |
| `preflight` | 自动预检空可选包 |
| `orphan-clean` | 检查场景孤儿脚本引用 |
| `dual-stub-clean` | 修复双 Stub 道具 |
| `prepare` | 准备并确认待构建场景；真实已完成 `n/N`，成功完成一关准备后才递增，不是当前正在处理的索引 |
| `build` | 构建本次 AssetBundle |
| `package` | 按本次构建清单收集交付文件，保留缓存 manifest |
| `zip` | 生成 zip 压缩包 |
| `restore` | 恢复 levelInfos、导出前场景与预览并清理 |

单集、多集、deps 共用同一快照和计时入口。deps 的 `preflight`、`orphan-clean`、`dual-stub-clean`、`prepare` 行为 `skipped`（不适用逐关卡阶段）；deps 仍保留构建前当前场景的安全准备。未发生的 compile 等阶段在收尾时标为 `skipped`，不能展示为执行完成。

前端每行 progress 和 elapsed 只展示实际后端快照：`total>0` 时按 `completed/total`，`total=0` 的运行行用不确定条，waiting/skipped/error 保留各自语义。历史 preflight **23.36 秒**（23358 ms）、orphan-clean **33.24 秒**（33240 ms）仅是上一轮日志，不可作为预算、倒计时、伪百分比或自动完成阈值。

旧后端缺少 `stages` 时仅显示原有 `phase/message` 文字，不合成阶段表。已有快照后遇到 `idle`、断网或域重载重连，保留已知行及计数/耗时，提示等待恢复，不清空、不补齐 done、不继续编造耗时；无历史快照则保持文字等待。失败面板保留原阶段错误和恢复结果，可由用户关闭；关闭面板不代表取消后端任务。

`GetStatus()` 在锁内构造新 DTO、新 `stages` 列表及每个新行对象，只读受锁保护的托管状态/计时器，不访问 Unity 主线程 API；监听线程 fast-path 可安全读取，调用方修改返回行不会污染生产状态。这是状态读取契约，不表示构建过程已在 Unity 验证。

仅 `queued` 长时间无进展时提示：等待Unity编辑器执行任务；若长时间不动检查编译/资源导入/模态弹窗。`compile` 长时间无进展应检查 Unity Console 编译错误与编译进度，等待编译和域重载后自动续跑；不要将这些状态一概归因于 Unity 未聚焦。

Runtime 源码新于编译 DLL 时，所有模式都会以 `phase=compile` 把参数、`mode` 和累计 `stages` 保存到 `SessionState`，编译域重载后恢复并自动续跑，已有阶段耗时不归零。一般阶段及同一域内累计使用 `Stopwatch`；仅编译挂起跨域、计时器无法存活的缺口以持久化 UTC 墙钟差补入 compile，负差按零处理，之后继续 `Stopwatch`，避免重复累计。重连后的 `idle` 不表示完成；应继续观察续跑、`done` 或 `error`。网络恢复/客户端等待超时后先读健康状态和全局任务状态，不要直接重复启动导出。当前 stdio `oc2_wait_export` 直接请求 Bridge，连接异常会退出此次等待；客户端仍需执行恢复后继续轮询。其外层 `elapsedMs` 是此次客户端等待时长，不是任一行耗时。

zip 写完后进入 `phase=restore`，记录 zip 耗时，恢复 levelInfos、原场景/预览并清理后记录 restore 耗时，最后发布顶层 `status=done/error`。执行阶段失败时，原行立即保留 `state=error`、消息和耗时，restore 独立转为 running 并记录自身结果；即使 restore 成功也不能抹掉原错误，最终仍为 `status=error`。restore 自身失败也保留错误。客户端必须等 restore 收尾，不能凭 zip 已生成或某行 error 就推断整个会话已结束。done 不等同预览行为验收；阶段计时不是固定总时长或加速倍数。30 分钟是客户端等待上限，不是完成保证，也不表示超时自动取消任务。

## 下载

当前首期提供导出状态，但未将二进制 zip 直接作为 MCP tool 返回。AI 可根据 `zipFileName` 调用现有 HTTP 下载地址，或由后续版本增加受控的临时下载文件工具。

成功后核对 `status=done`、`zipFileName`、`fileCount` 和任务集名，再通过 `GET /api/set/export/download?setName=<集名或多集连接名>&fileName=<zipFileName>` 下载（参数 URL 编码）。整体解压目标是 `BepInEx/plugins/`：关卡在 `OC2DIYLevel/levels/<set>/`，依赖包在同级 `OC2DIYLevelRuntimeWLoader/`；levels 模式不包含后者。
