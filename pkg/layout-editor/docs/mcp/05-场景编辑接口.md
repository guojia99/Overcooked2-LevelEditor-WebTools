# 场景编辑接口

## 读取

调用 `oc2_get_scene_layout`，参数：

```json
{ "assetPath": "Assets/LevelSets/tester_web/scenes/level_1.unity" }
```

返回 `LayoutDocument`，包括物品、地板、可行走区域、死亡配置、动画组、开关联动、相机和灯光。

### 相机（`cameraInfo`）

- `cameraInfo.splitScreen`（bool）：多镜头分屏开关。写回后相机 Camera 子物体带 `SplitScreen|2|C0:...|C1:...` 载体 tag；运行时按场景内本地厨师数量自动 1/2/3/4 镜头（单人双厨师 = 2），每个镜头跟随对应厨师，原版镜头屏蔽且忽略 `cameraInfo.position` 出发点偏移。开启后运行时单向，不会切回单镜头。
- `cameraInfo.splitScreenCameras`（数组，镜头 1..4）：`{ visible, offset:{x,y,z}, fieldOfView, size }`。offset 相对玩家位置，FOV<=0 沿用主相机，size=距离倍率；visible=false = 编辑器不画参考且运行时该玩家画面不生成（保留黑框）。写回编码进同一 tag 的 `C0..C3` 段。
- `cameraInfo.intro`（进场动画，对象）：`{ mode, duration, startDistance, rotateAngle, focusTarget:{x,z} }`。写回由 `CameraIntroBakery` 落到相机 Camera 子物体 Animator（controller 整替，不改 common01 原版资产），结束画面恒为最终镜头：
  - `mode`：`vanilla`（恢复原版 PullBackIntro，默认）| `none`（禁用 Animator，开场即最终画面）| `pullBack`（参数化拉近）| `rotateLeft` / `rotateRight`（偏航旋入，左右方向）| `focus`（镜头水平平移到 `focusTarget` X/Z 上方特写再滑回）| `tour`（巡回进场：镜头在 `tourA.x` → `tourB.x` 的 X 轴上方水平巡航 → 归位；两段折线、段时长按距离比例分配）| `dollyIn`（推近：起始在最终位的视轴远端 → 滑入）| `dive`（俯冲：起始更高 `diveHeight` 米且视轴更远 → 俯冲滑入）| `orbit`（环绕：绕最终位竖直轴圆弧滑入，`orbitAngle` 90–360°、`orbitDirection` left/right、`startDistance` = 环绕半径）| `raft` / `space`（官方 DLC 变体 controller：进场 + 待机木筏摇曳 / 太空 roll 循环，待机行为一并切换）。
  - `duration`（秒，默认 2，0.5–6）、`startDistance`（米：pullBack/rotate/dive/dollyIn 默认 5，orbit = 环绕半径默认 8）、`rotateAngle`（度，默认 30，5–90）、`diveHeight`（米，默认 10，2–40）、`orbitAngle`（度，默认 180，90–360）、`orbitDirection`（left/right，默认 right）按模式生效。**focus/tour 为水平平移**：与主相机同高度/同朝向（画面= 最终画面平移，构图恒一致、无贴地黑屏）。**focus 的 `focusTarget` X/Z 均生效**；**tour 仅 X 生效**（`tourA`/`tourB` 的 Z 恒为主相机 Z）。坐标不钳制（大地图可选远处；编辑器选点超出主相机画面范围 ±0.75×水平半宽时仅提示"途中可能经过空旷区域"）。
  - 读回验证：`oc2_get_scene_layout` 的 `cameraInfo.intro` 由 Animator 现状反推（自定义模式参数存 controller 内嵌 `IntroSource` 子资产，`Assets/LevelSets/<set>/animations/cameraintro_<scene>.controller`）；写回后重新读取应得到相同 mode 与参数。
  - `intro` 为 `null`/缺省时写回不改动进场配置（防旧文档误清）；`mode:"vanilla"` 为显式恢复原版并清理烘焙资产。分屏开启时运行时原版镜头被屏蔽，进场动画不可见（前端禁用配置）。
- 仅全量写回携带；作用域写回（`only=items|decor|floors`）不改动相机。

### 开关 / 压力地板调色（`items[].switchStub / pressureSwitch`）

- `switchStub.idleColor` / `switchStub.pressedColor`：普通开关/大炮开关的未按下/按下颜色（`#rrggbb`，空=不染色）。
- `pressureSwitch.idleColor` / `pressureSwitch.pressedColor`：压力开关与 DLC13 莲花压力地板的未受压/受压颜色。
- 颜色采用乘法染色（保留原贴图纹理；OC2 gloss 写 `_MaskColor`，Standard 写 `_Color`），金属度/粗糙度/边缘光/高光保留原材质；写回后生成 `Design/Switch Tint Logic` helper；编辑器场景视图显示未按下色，按下/受压色在 Play/真机按状态切换。依赖包需为含 `CustomStub.SwitchTint` 的新版本。

### 压力开关按住式门（`animControls.groups[].advanceMode === "hold"`）
- `triggerMode` 必为 `"button"`，组内固定两个 `rotate` 事件：事件 1 = 站上开门，事件 2 = 离开关门。
- 仅允许压力开关作为 `buttonLinks[].sourceId`；`lockUntilFinished` / `sequenceMode` 不参与烘焙。
- 写回时 `ButtonLinkBakery` 不创建 `Design/Button Logic` helper，而是把开门/关门触发器写进压力开关
  `PseudoPrefabPressureSwitchStub.triggerOnAnimatorEnter/Exit`，`animatorToTrigger` 指向组根 Animator。
- 回读由压力开关 stub 反查 hold 组重建 `buttonLinks`；`AnimGroupSource` 内 `advanceMode:"hold"` 无损往返。

### 摇杆操控组（v10+，`animControls.groups[].groupKind === "pilot"`）

动画组集合里 `groupKind="pilot"` 的条目是**摇杆操控组**：整组成员（`itemInstanceIds/floorInstanceIds/objectInstanceIds`，含地板、核心层、装饰）在写回时烘成原版 `PilotMovement` 刚体，玩家在 `terminalInstanceId` 指向的摇杆（Terminal 物品，目录名「摇杆」/「摇杆（加农炮）」，调色板「核心 · 摇杆」分组）上按交互键后驾驶整组水平移动（成员相对位置不变，松杆吸附网格中心，联机自动同步）。字段：`terminalInstanceId`（绑定的摇杆 item id，写回前必须配置，否则前端校验阻断）、`moveSpeed`（米/秒，默认 2.5）；`waypoints/events` 恒空。约束：成员不能同时属于动画组与摇杆组（前端阻断）；不支持 `partId` 分 P；行走面为整组单一矩形包围盒（空洞填平，写回时告警）。摇杆灯（ControlTerminal_Marker，`items[].stubKind === "MarkerLight"`）可经 `items[].markerLight.joystickInstanceId` 绑到某摇杆——运行时灯色跟随占用状态（有人驾驶 = 绿灯亮）。读回验证：`oc2_get_scene_layout` 的该组 `groupHierarchyPath` 位于 `Design/Pilot Objects/<组名>`。

### 动画事件类型（v11+：scale/tilt/orbit/fade + 缓动/弧线）

`animControls.groups[].events[]` 支持的成员动画事件类型：

- `"move"`：路点路线；`easing`（linear/easeIn/easeOut/easeInOut/easeOutBounce/easeInOutBack）作用于每段进度；waypoint 级 `ctrlHas/ctrlX/ctrlZ` 为该段二次贝塞尔控制点（弧线路径）。
- `"rotate"`：绕自身 Y 轴自转（支持 `easing`/`pingpong` 往返摆动）。
- `"scale"`：缩放，`scaleTo`（相对初始尺寸倍率：0=缩到 0 消失、>1=放大）+ `scaleSeconds`；`loop`=脉冲、`pingpong`=呼吸；网格占位不受影响（桌台类缩没后仍占格，碰撞体随缩放退化）。
- `"fade"`：淡入淡出（隐身/显型），`fadeTo`（0=全透明隐身、1=不透明显型）+ `fadeSeconds`；`loop`=闪烁呼吸。材质 alpha 渐变由 `CustomStub.FadeDriver` 运行时驱动（透明材质全程渐变；不透明材质两端准确——≈0 彻底消失、=1 复原）；网格占位与碰撞不受影响。与 scale 缩没是两种不同演出。
- `"tilt"`：翻转/倾斜，`tiltDegrees`（-180~180 带符号）+ `tiltAxis`（"x" 俯仰 / "z" 侧倾）+ `tiltSeconds`；`pingpong`=往返摆动（缓慢晃动 = 小角度+长用时）。
- `"orbit"`：公转，`orbitCenterX/Z`（圆心世界 XZ）+ `orbitDegrees`（默认 360）+ `orbitSeconds` + `orbitDirection`；每成员半径=初始位到圆心距离；`loop`=持续公转。与 move/其他 orbit 时间区间互斥（写回校验报错），与 lift/drop 可并行。
- `"lift"/"drop"/"wait"`：见既有语义（lift/drop 也支持 `easing`）。

时间重叠即并行（烘焙为组合 clip）；rotate/tilt/scale/fade 为叠加通道可与位姿事件并行。读回经组 controller 内嵌的 `AnimGroupSource` 无损往返。fade 需依赖包 ≥ 4.0.0（旧包安全降级为无淡出）。

### 分 P 字段（v9+，透传只读）

分 P 关卡（多阶段布局，规格见 `docs/10-分P关卡功能规格.md`）的文档额外携带：

- 顶层 `partLevel`：`{ enabled, parts[{id,label,park,axis…}], transitions[] }`；
- 物品/地板条目上的 `partId`（`"base"` = 全程常驻，`"p1".."pN"` = 对应阶段）。

这些字段由编辑器 UI 管理（真源 = 关卡数据目录 `part_level~/part_level.json`），**MCP 侧视为只读**：`scene-patch` 操作不要改写 `partId/partLevel`（写回侧有不可逆守卫会拒绝降级）；需要调整阶段归属时提示用户在编辑器「右键 → 移到分 P」操作。

## 草稿编辑

创建草稿：

```json
{ "setName": "tester_web", "levelId": "level_1", "assetPath": "..." }
```

移动物品：

```json
{
  "draftId": "draft-...",
  "operations": [
    { "op": "move_item", "instanceId": "u:123", "position": { "x": 3.6, "y": 0, "z": 4.8 } },
    { "op": "rotate_item", "instanceId": "u:123", "y": 90 }
  ]
}
```

支持的 Patch：`move_item`、`rotate_item`、`delete_item`、`add_item`。`add_item` 必须提供完整的目录物品数据，不能只传一个未经查询的名称。

## 提交

提交前必须调用验证和 diff；提交调用：

```json
{ "draftId": "draft-...", "confirm": true, "snap": 0.01 }
```

写回会触发 Unity 场景保存、依赖处理和伪预制体刷新，预计 5-60 秒。失败后不要盲目重试，先重新读取场景和写回历史。Unity 处于 Play 模式（或正在进入/退出 Play）时写回直接 400，场景和关卡数据都不会改；退出 Play 后再提交。

### 一次性迁移（茶杯回收台）

旧关卡的 `web_teacup_return` 可能带着历史默认值 `plateReturn.returnClean=true`。写回（及导出 prepare）会把**写回前已存在的旧实例**一次性改为 `false`（`data/<level>/layout_migrations~/layout_migrations.json` 落标记；新关卡创建时已写基线），本次新建实例或之后手动勾选的 `true` 会保留。读取/写回后以 `oc2_get_scene_layout` 返回的 `plateReturn.returnClean` 为准；如需干净茶杯回流，在对应回收台的右键面板重新勾选并再次写回。
