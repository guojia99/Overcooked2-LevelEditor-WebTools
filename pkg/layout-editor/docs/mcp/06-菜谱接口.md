# 菜谱接口

`oc2_get_level_recipe_context` 同时读取关卡菜谱和菜谱目录，减少 AI 自行拼接多个请求。

目录 `catalog.recipes[].saladSubgroups` 为只读计算字段（不新增接口或提升版本）：

- 仅内置 `type=salad` 生效；`group=levelset` 或 `Assets/LevelSets/` 路径返回空数组，本关沙拉仍独立展示。
- `non_dlc11_official`（非DLC11官方沙拉）：去掉下列酱料 ID 后，非酱叶食材非空且全部属于 `LettuceSO/TomatoSO/CucumberSO`，独占此组并提前返回。当前为剧情 3 道及其 9 道单/双酱扩展，共 12 道；不能仅按 `isCustom=false` 判断。
- 其余沙拉按 `mustard_only`：含芥末且不含番茄酱；`ketchup_only`：含番茄酱且不含芥末；`both_sauces`：两者都有；`no_sauce`：两者都没有。四组互斥，与 `non_dlc11_official` 合计覆盖内置沙拉。
- 食材 ID 按实际叶食材匹配：`mustard/DLC08_Mustard/dlc11_mustard` 与 `ketchup/DLC08_Ketchup/dlc11_ketchup`；不从菜名猜酱料。
- `official` 表示剩余 `isCustom=false` 的内置官方来源，可与酱料组交叉；当前为 DLC11 的 6 道，与无酱交叉。剧情 12 道独占新组，commonW3 的 CustomRecipeSO 不属于 `official`。
- Web 菜谱清单和编辑器弹窗按相同规则计算，兼容既有目录快照。交叉卡片按菜谱 ID 同步勾选，父组/已选数量按唯一 ID，保存仍按现有 GUID 写入。组头「全选本类 / 全选」与逐卡勾选等价（按 recipe id 同步交叉副本），不新增 HTTP 字段或写入路径。
- 本字段无写入副作用。验证：对比 `/api/recipes?levelSet=` 与静态 `recipes/<group>.json` 的相同菜谱；Web 勾选/取消官方组卡片后，酱料组副本应立即同步。保存菜谱后用 `oc2_get_level_recipe_context` 读回 `levelRecipes`，每道仅保存一次。
- 离线回归也覆盖选择菜谱弹窗的组头全选/取消：批量勾选按 recipe id 去重、重复卡片同步，不产生额外 GUID。

离线回归：`node layout-editor/scripts/check-salad-groups.cjs`（需先安装 web 依赖）。覆盖三套酱料 ID、剧情 12 道独占及精确成员、混合/未知/空叶食材回落、四组互斥、官方交叉、本关排除、弹窗重复卡片同步／唯一计数，以及实际资产扫描与前端镜像一致性。`--live` 额外比较在线 `/api/recipes`、共享库 `/api/custom-recipes?libraryId=commonw3` 和 public/dist 静态目录的沙拉 ID/GUID/组成/分组；可用 `OC2_UNITY_URL` 指定桥地址，HTTP 超时 90 秒，失败直接退出非零，不写关卡。

参数：

```json
{ "assetPath": "Assets/LevelSets/tester_web/data/level_1/LevelInfo.asset", "levelSet": "tester_web" }
```

当前首期 MCP 不直接提供菜谱写入工具。原因是菜谱保存会联动 Optional、CookingSteps、DLC Matchlist、火锅/烤盘许可食材和 bundle 依赖，需要先把后端返回的派生变化完整纳入验证和 diff。

AI 可以使用场景工具和只读菜谱上下文进行规划；菜谱写入接口将在补齐派生结果契约后加入 manifest。

## 2026-11 订单顺序（4.0.0）

`oc2_get_level_recipe_context` 返回新增 `orderSequence` 只读字段（旧桥无该端点时为 null）：`{ exists, json }`，
json 内为 `LevelOrderSequence`（`enabled / endBehavior(loop|pingpong|stop) / groups[].{mode(0按序|1随机), batchSize(抽菜数,0=整池,≤999), recipeGuids[]}`）。

- 语义：ordered 组按序出（可重复）；random 组抽批内跑原版防重复随机，出满 N 单换组；全部播完后 loop 循环 / pingpong 钟摆倒序 / stop 停止出单。
- MCP 首期不提供写入工具（同菜谱写入理由）；写入走 Web 菜谱管理「订单顺序」tab（`POST /api/level/order-sequence-save`）。
- 场景载体（组件 + `OrderSeq|` tag）由写回/导出幂等烘焙（`LayoutEditorOrderSequenceBake`）；改配置后需写回本关或导出关卡集才生效。

## 2026-11 commonW3 酱沙拉集成

权威配方与图标共用清单：`layout-editor/scripts/data/salad-sauce-recipes.json`。剧情 3 + DLC11 6 + Web 21 按叶食材 UID 去重为 26 个基底，每基底生成 Ketchup / Mustard / KetchupMustard，合计 78 个出单菜谱。原 21 个 Web 沙拉 UID/GUID 保留。`sourceIds` 包含被去重的原配方别名，`baseId` / `ingredients` / `iconGuid` 为图标合成输入。图标 GUID 为 md5(`commonw3-icon:<完整新ID>`)；生成器不写 PNG 或既有 icon meta。

保存含酱沙拉的菜谱时自动合并非出单 optional：每个食材锚点 × 三种酱态，共 24 个节点，只接住至少一种沙拉食材的部分态；叶节点额外登记以供联机 UID 反序列化。空盘接酱、重复同色酱在临时转移前拒绝，`ServerPlacementContainer.HandlePlacement` 再复核。接酱后仍可加菜，双酱先后不限。成品组成只用 DLC11 酱 UID 890084 / 890076；DLC08 158482 / 17094 仅在沙拉转移边界显式归一化，热狗不改。

静态目录、在线菜谱目录和 custom-recipes 管理列表仅按 factory 的真实前缀 `Web_SauceSalad_Optional_` 排除内部锚点，不按 score=0 泛判；底层资产扫描、optional 依赖登记及原生网络序列化仍保留全部 24 个。可选沙拉强断言为 108 = 原 Web 21 + 新酱沙拉 78 + 官方原菜 9（原四组成别名保留）；commonW3 为 99。非DLC11官方沙拉独占 12 道后，三种酱组各 23，无酱 27，official 6（仍交叉无酱），父组唯一总数 108。离线回归同时强制普通零分条目不被此规则过滤；重新编译后以 `check-salad-groups.cjs --live` 检测旧在线程序集或陈旧静态产物，用 `GET /api/recipes/salad-sauce` 读回原生 optional/序列化验证。仅分组调整只需编译、刷新静态目录和读回 `/api/recipes`，无需重建配方或 bundle。

开发重建闭环（不增加 MCP 字段/工具，不改关卡）：

1. `node layout-editor/scripts/gen-commonw3-salad-sauces.mjs --apply`；重复执行 `--check` 应返回 changed=0。
2. `POST /api/compile`（空 body，需 Content-Length: 0），然后轮询 `/api/health` 直到恢复。Refresh 触发域重载时连接中断属预期，建议最多等待 180 秒。
3. `POST /api/recipes/salad-sauce`，或菜单 `Layout Editor/Recipes/Rebuild Salad Sauce Assets`，在 commonW3 生成两份原生载体和两份酱视觉 prefab。同步操作，HTTP 超时建议 90 秒；若断线，先 GET 同一端点读回，避免盲目重写。工厂只更新 commonW3，不保存场景或 LevelInfo。
4. `GET /api/recipes/salad-sauce` 做原生配方/部分态/拦截/外观/依赖检查，返回 `ok/finalRecipes/optionalAnchors/nativeChecks/meshes`。它会创建并销毁隐藏测试对象、临时启用后恢复沙拉补丁开关，不进入 Play，不写用户数据。
5. `node layout-editor/scripts/check-salad-sauces.mjs` 校验 UID/引用去重、模型脚本引用及原 21 配方和图标字节未变；随后运行现有 `build-catalog.mjs` 刷新静态目录。
6. `node layout-editor/scripts/check-salad-sauces.mjs --live --report` 连续两次工厂重建并比较 12 个文件 SHA-256，再 GET 读回；结果和完整 78 配方映射写到 `layout-editor/reports/salad-sauce-integration/`。独立编译入口为 `layout-editor/offline-check/LayoutEditor.Standalone.Check.csproj`。

### 仅构建沙拉依赖 Bundle

`POST /api/recipes/salad-sauce?operation=build`（空 body 或 `{}`）先返回 `queued`，再由 Unity delayCall 构建。MCP 对应 `oc2_salad_sauce_bundles {operation:"build",confirm:true}`；读回使用 `{operation:"status"}` / `GET /api/recipes/salad-sauce?operation=status`。编译失败、Play、导入/编译中、runtime DLL 过期均拒绝。通过现有 staging 后复查守卫，不在 build 前调用 Refresh。

只传 `commonw3`、`webcustomstub_runtime` 两项 `AssetBundleBuild[]`，Windows 目标，输出 `Library/SaladSauceBundleBuild/Windows`，不触发场景 Prepare/Save、LevelInfo 写回、全工程 bundle 设置修改或 zip 发布。显式映射可能把其他库引用嵌入这两包，需查看资产/贴图重复报告，不能把本输出当完整依赖发布包。

状态持久化 `Library/SaladSauceBundleBuild/result.json`，含 `queued/building/completed/failed`、错误、构建时间、大小/SHA256、资产名、依赖、78 图标/配方、24 锚点、两 mesh/material/texture、carrier 脚本与原始 lookup 载体引用、runtime DLL 三方 hash 和场景状态。runtime lookup 本身按设计序列化为空，由 Awake 从原始 carrier 克隆；完整原生行为仍通过无 operation 的 GET 验证。贴图重复比较两包实际加载的 Texture2D 原始数据 hash。

建议 2 秒轮询，最长 30 分钟。BuildPipeline 占用 Unity 主线程时 HTTP 可超时；此时直接读共享目录的 result.json，等待完成后再 GET。遇到断线/超时必须先读状态，不能再次 POST。域重载后遗留 queued/building 不会自动续建，确认 Unity 已空闲并检查日志与文件后才能重试。

Unity 非 CPU 可读贴图的 `GetRawTextureData()` 可能返回空数组，状态将其列入 `textureHashesUnavailable`，绝不把空 hash 当重复。构建完成后运行 `python3 layout-editor/scripts/validate-salad-sauce-bundles.py`（需要 UnityPy），从实际 bundle 的 Texture2D 序列化像素读取 hash/大小/格式，检查三个脚本类型和 DLL，重新调用原生 GET 并追加 `reports/salad-sauce-integration/bundle-validation.md/json`。同一构建时间的重复校验更新同一条记录。

导出识别选中酱沙拉后写入 `saladsauce` 清单特征，运行时逐关门控；补充 bundle18/47/427/428/354（仅注册已存在 bundle）。commonW3 与 `webcustomstub_runtime` 需重新构建后随依赖包分发，发布号仍为 4.0.0。MCP 的已有菜谱上下文可直接读回新增菜谱和既有 `saladSubgroups`，无新写入工具。
