# 安全与确认

MCP 只服务关卡编辑器，不提供：

- 任意文件读取或写入
- Shell、Git 或 Unity 菜单执行
- `Assets/Scripts`、`Assembly-CSharp-Patch`、`BepInExPlugins` 修改
- 无确认的删除、重命名或覆盖

当前写场景、导出及原生模式保存/切换/创建必须显式传 `confirm: true`。场景草稿写回必须先完成：

1. 创建草稿
2. 应用 Patch
3. 验证草稿
4. 查看 Diff
5. 显式确认提交

导出是长任务并可能覆盖构建产物，必须先确认。删除关卡集、删除关卡（含批量删除）、自定义资产上传和任意依赖写入暂未加入首期 MCP。

原生模式写工具不经过场景草稿，按后端原生模式守卫执行。保存配置只改本关 sidecar/专属 SO，切换会改控制器和必要绑定，创建会生成场景/关卡数据。三者均强制自动读回，不绕过脏场景/唯一 Manager/Horde 门具/原生转场/分 P 冲突检查。切换前先查看场景与模式差异，明确目标模式后调用；接口及错误恢复见[原生模式接口](10-原生模式接口.md)。

`oc2_change_level_mode.convertHordeObjects` 默认 false，仅在用户明确同意改变交付窗外观与组件后传 true。`confirm:true` 必填，但不代表可以自行开启转换；失败也不自动改 flag。true 仅原子双向转换受支持普通 ServingStation / Horde Service_Window wrapper，保留原 GO/位置/名称/回收绑定；切出时不要预删最后 Horde 窗，金币 gate 须另行删除，正常 Horde 无须金币 gate。
