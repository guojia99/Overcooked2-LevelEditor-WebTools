# 错误与重试

统一错误结构：

```json
{
  "ok": false,
  "error": { "code": "BRIDGE_ERROR", "message": "...", "retryable": true },
  "bridge": { "online": false, "url": "http://10.211.55.3:8765" }
}
```

处理建议：

- `BRIDGE_ERROR` 且 `retryable=true`：等待 3 秒后重试健康检查。
- HTML 响应：Unity 正在域重载或 Bridge 与前端版本不一致，不要立即重复写操作。
- `NOT_FOUND`：检查关卡集、关卡和 assetPath，不要猜路径。
- 草稿操作失败：保留原 draft，修正 operation 后再提交。
- 写回超时：先调用场景读取和写回历史，不要直接重复 POST。
- 写回返回「Play 模式，写回已全部拦截」：Unity 仍在试玩或正在进出 Play，整次写回未落盘。退出 Play 后再提交，不要立刻重试。
- 导出超时：查询导出状态，确认 Unity 是否仍处于 build 阶段。
- 导出启动响应丢失：结果未知，先读取全局状态及 exportId，禁止自动重放 POST。stdio 等待连接/HTML 暂态会在 deadline 内恢复；exportId 被替换则停止等待。非编译阶段域重载会发布 error 并尝试恢复场景和备份，检查恢复结果后才能重新启动。
- 下载繁忙（503）或下载超时只重试 download，不重新构建。ThreadAbort 在域卸载期间正常退出且不 ResetAbort；它不能单独证明导出失败根因。

只有 manifest 中 `safeToRetry=true` 的读操作可以自动重试。写场景和导出默认不可自动重试。

模式写工具还区分 `INVALID_ARGUMENT/not_started`、`WRITE_UNCONFIRMED/unknown`、`READBACK_FAILED/acknowledged`（后者值在 data.writeOutcome）。所有模式写错误都 retryable=false，并保留实际 write_asset/write_scene 副作用。POST 已成功但 GET 失败时，只补 GET 验证，不能重放保存/切换/创建；创建先查关卡列表。详见[原生模式接口](10-原生模式接口.md#结果超时与恢复)。
