# 08 · 自定义内容管理（食材 / 锅具 / 工作台 / 水槽 / 托盘 / 备餐容器 / 分料机）

> 前端路由：`/custom-content`；后端：`Assets/Editor/LayoutEditor/LayoutEditorCustomContentApi.cs`。
> 资源按关卡集保存：`Assets/LevelSets/<set>/custom_content/`，bundle 名 `<set>/custom_content`。
> 模板只读：`Assets/common04`、`Assets/common03`、`Assets/common02`、`Assets/commonW1`、`Assets/Modules`。

## 1. 页面结构

| 路由 | 内容 |
|---|---|
| `/custom-content` | 选择关卡集 |
| `/custom-content/{set}` | 自定义类型总览（食材/工作台/锅具/水槽/托盘/备餐容器/分料机 + 自定义菜谱/汉堡/夹心入口） |
| `/custom-content/{set}/{kind}` | 列表（图标、模板、资产状态告警；bundle 未构建不算告警——创作期正常，导出时自动产出） |
| `/custom-content/{set}/{kind}/new`、`/{id}` | 新建/编辑表单 |

kind：`ingredient`、`counter`、`utensil`、`sink`、`tray`、`prep`、`splitter`。

## 2. 目录与资产

```text
Assets/LevelSets/<set>/custom_content/
  Config.asset                 # 管理页索引（显式不赋 bundle 名）
  ingredients/<id>/<id>.prefab
  counter/<id>/<id>.prefab
  utensil/<id>/<id>.prefab
  sink/<id>/<id>.prefab
  tray/<id>/<id>.prefab
  prep/<id>/<id>.prefab
  splitter/<id>/<id>.prefab
```

每个条目还会生成：

- `<id>_SO.asset`：独立 `PseudoPrefabSO`（`asset` 直引 prefab，避免 embedded SO 无法按 GUID 往返）
- `<id>_Node.asset`：食材/备餐容器的独立 `IngredientOrderNode`（可选图标、uID、plating）
- `<id>_Icon.png`、`models/`：上传的图标与模型

模板克隆使用 `AssetDatabase.CopyAsset` + `PrefabUtility.InstantiatePrefab` + `ReplacePrefab`（Unity 2017 兼容）。`.meta` 由 Unity 生成/保留，不手写 GUID；common04/Modules 模板永不修改。

## 3. HTTP API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/custom-content/templates?kind=` | 模板列表 |
| GET | `/api/custom-content/meta` | 站台类型（PseudoPrefabCookingUtensilStub.CookingStationType，含 zh/en 标签） |
| GET | `/api/custom-content/list?setName=&kind=` | 列表（含 `hasModel`/模型变换回读、`updatedAt`、告警） |
| GET | `/api/custom-content/options?setName=` | 表单引用选项（prefab/SO/模型/槽位/菜谱/装盘/音效） |
| GET | `/api/custom-content/hierarchy?assetPath=` | prefab 子物体路径（水槽部件/分料机模型） |
| GET | `/api/custom-content/catalog?setName=` | 动态素材面板条目（可放置 kind） |
| GET | `/api/custom-content/icon?assetPath=` | 图标 PNG |
| GET | `/api/custom-content/model-source?assetPath=` | 3D 预览模型文件 |
| POST | `/api/custom-content/create` / `update` / `delete` | 资产工厂（错误以 `{"ok":false,"error":…}` 透传） |

### 3.1 create/update 语义要点（2026-11 修复版）

- **id 校验**：仅 ASCII 字母/数字/下划线，拒绝而非改写；**同一关卡集内跨类型唯一**（catalog 按裸 id 索引）。
- **orderUid**：手填值做全工程 IngredientOrderNode 查重，冲突直接报错；0 = 自动分配。
- **clearFields[]**（仅 update）：显式清除引用字段（空 guid = 保持原值的旧语义不变）。支持：`platingStepId`、`restrictionsGuid`、`cosmeticsPrefabGuid`、`nextPrefabGuid`、`progressUiGuid`、`ingredientContentUiGuid`、`fireEffectGuid`、`chopPfxGuid`、`tutorialIconGuid`、`sludgeGuid`、`spawnEffectGuid`、`cleanPlateStackGuid`、`washingPartPath`、`dryingPartPath`、`traySlotGuid`、`inputRecipeGuid`、`outputPrefabGuid`。
- **图标**：只接受 PNG magic（前端会把 JPG 转 PNG）；Sprite 为空时报错而非清掉模板默认图标。
- **可加工下一形态联动**：`nextPrefabGuid` 非空时创建即显式关联（校验 GUID 可解析），并**跳过自动 `_Unworkable` 克隆**；前端「🔪 切片形态」区据此一条表单完成 整体+切片+自动关联（先建切片条目、回填 GUID 再建主体）。
  - **OrderNode 始终补建**（2026-11 修复）：`ingredient_workable` 模板自带 `nodePath` 为空，无论是否显式关联切片，都会克隆一个独立 `<id>_Node.asset`（订单/菜谱/图标/切割成品匹配都依赖它）；跳过自动克隆只影响 `_Unworkable.prefab`。旧版「显式关联」路径漏建该 Node（列表报 `OrderNode 缺失`）——编辑保存时 `Update` 会自愈补建并接线，无需删除重建。
- **模型**：主模型落盘改名 `<id>.fbx/.obj`（+`<id>.mtl`），贴图按类别命名 `<id>_<class>.<ext>`；前端改写 FBX/MTL 内贴图引用，中文/空格文件名安全；`<id>_Model.prefab` 重传时**原地替换保 GUID**。
- **模型变换**：`modelScale/Position/Rotation/Pivot` 与文件上传解耦——无新文件也写变换（`ApplyModelTransform`）；list 回读已存值供表单回显。
- **Create 回滚**：任一步失败删除已建条目目录并清理 Config；SaveIcon/SaveModel 失败以错误返回（HTTP 400）。
- **Delete 顺序**：先删资产目录、成功后才移除 Config 条目。
- **模板不可变**：update 携带与创建时不同的 `templateId` 会被拒绝。

## 4. 锅具站台与锅内模型

`LayoutCookingUtensilStubDto` 新增：

- `stationTypes[]`：`Hob` / `Oven` / `DeepFatFryer` / `FirePit` / `Flamethrower` / `Barbeque` / `Invalid_FloorBurner`
  - 火锅 = `Invalid_FloorBurner`（宿主 `CookingStationType.FloorBurner`）
  - 烤盘 = `Oven`，煎盘/篝火 = `FirePit`，烤串 = `Barbeque`，汤锅/蒸笼 = `Hob`
- `modelGuids[]` / `modelSoGuids[]`：锅内食材展示模型（与额外食材顺序对应）

写入/回读在 `LayoutEditorStubIO` 的 CookingUtensil 分支；前端控件在 `stubControls.ts` / `utensilManager.ts`。

## 5. 真机

- `common04` 仅作为编辑器克隆模板，不随依赖包 `OC2DIYLevelRuntimeWLoader/` 导出。
- 自定义 prefab 的 `SetupCustom*Stub` 字段由 `Assets/WebCustomStubRuntime/CustomContent/CustomSetupRuntime.cs` 在真机等价执行。
- `TriggerOnChild` / `Bellows` / `cobble` / `DestroyComponentOfChildStub` 由 `UpstreamPseudoHeal.cs` 运行时重放。
- 依赖包 `webcustomstub_runtime` 现在同时携带：`LevelEditorStub.dll`、`IngredientSplitterStub.dll`、`IngredientSplitterRuntime.dll`、`WebCustomStubRuntime.dll`；Loader 按依赖顺序加载。
- 分料机运行时源码在 `Assets/WebCustomStubRuntime/Modules~/IngredientSplitter/`（`~` 目录 Unity 忽略，dotnet 单独编译）。
- **2026-11 上游字段迁移**：`IngredientSplitter.outputPrefab(GameObject)` → `outputPrefabSO(PseudoPrefabSO)`。模板/存量场景的旧引用由 `LegacyOutputPrefab`（`FormerlySerializedAs`）接住，`LayoutEditorIngredientSplitterMigration` 在场景打开/自定义内容读写/写回/导出时自动解析为 PseudoPrefabSO；运行时模块通过 `RecipeHelper.GetIngredientPrefabForOptional`（反射，失败回落直接加载）套用 optional 组装输出。
- **逐关卡导出保留自定义 bundle**：按关卡筛选导出时 `custom_content` / `custom_recipes` 与 `info_<set>` 一并保留（它们是 info 的登记依赖，剔除会导致真机加载失败）。

## 6. 前端（2026-11 分层重构版）

- 页面结构与交互对齐自定义菜谱（`customRecipes.ts`）：SPA pushState 导航（无整页刷新）、分层卡片表单（素材准备 → 模板 → 基本信息 → 类型参数 → 图标 → 模型）、顶部+底部双保存、列表搜索/标签、样式化删除确认。
- **所有参数字段带 tips**（如「可加工下一形态」说明切割链路与前置条件）；站台/模板/字段均有中英双语。
- 引用字段编辑态支持「✖ 清除 / ↩ 撤销」（走 `clearFields`）；引用多选器带搜索、中英文、保序（#N）。
- 图标：选择即预览，JPG 自动转 PNG；模型：贴图按文件名分类、FBX/MTL 引用改写、变换只在 3D 预览里调（保存写回）。
- 校验：id 正则、中文名必填、分料机输入/输出必填、锅具至少一个站台、uID 非负整数。
