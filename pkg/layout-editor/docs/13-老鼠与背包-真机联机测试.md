# 老鼠与储物背包：真机联机修复测试

发布版本保持 **v4.0.0**。本次内部修订为 **4.0.0.22（2026-11-11）**，不改变
`StubVersion.Value`、`Loader.PluginVersion` 或 `requires.txt` 的 semver。

## 修改内容

- 老鼠在实体扫描前完成装配，补齐原生 `RigidbodyMotion`，主机导航，客机通过
  `WorldObject/BasicLerp` 跟随。客机不再独立选目标、巡逻或模拟受击。
- 偷取提交时复查食材当前位置、距离、高度、可拾取状态；确认挂嘴成功才记录携带。
  掉落和销毁前检查物品仍属于本鼠，失败路径清理目标占用和携带状态。
- 背包按格保留精确 prefab、加工阶段和切菜进度，原料、半切、切后可混存。
  `CookableIngredient` 的零烹饪进度食材也可存；已经开始烹饪的状态仍拒绝。
- 食材目录在扫描前冻结，使用独立分页生成表，避免原生四位生成编号溢出。
  双端通过 BackpackProtocol 核对目录和实体 ID；不一致时保留实物并拒绝新存取。
- 取出确认恢复状态、挂接和手槽成功后再扣库存。异常恢复期间锁住该笔事务，
  不销毁仍在他人手中或挂点上的物品，也不允许待恢复物被原生交互重复消费。

## 构建与安装

1. 在仓库根目录构建协议模块。Release 构建目标会自动把 DLL 放入 RuntimeDll，
   对应 `.meta` 已指定 `webcustomstub_runtime` bundle。

   ```sh
   dotnet build Assets/WebCustomStubRuntime/WebBackpack/Modules~/BackpackProtocol/BackpackProtocol.csproj --configuration Release --nologo --verbosity minimal
   ```

2. Unity 刷新并等待脚本编译完成。正常导出前的 `LayoutStubDllBuilder.StageRuntime`
   会 staging 主运行时，同时校验协议 DLL 是否存在、是否落后于模块源码；
   缺失/过期会中止导出，不能用旧 bundle 代替。
3. 重新导出依赖包，**主客机安装同一批依赖包并完全重启游戏**。本次不改场景数据格式；
   已含 `rat` / `webbackpack` 清单和完整素材依赖的关卡不要求重新写回。
4. 日志应出现 `[RatNet] scan preparation revision=4.0.0.22`（含老鼠关卡）或
   `[BackpackNet] revision=4.0.0.22 directory hooks installed`（含背包关卡）。
   只有 `v4.0.0` 版本行不足以证明安装的是本次产物。

本次离线检查不等同于 Unity 编译或 AssetBundle 构建。当前 Unity 桥地址
`10.211.55.3:8765` 探活超时，尚未通过该桥执行重编译、staging 或导出。

## 开启日志

主客机都在游戏退出后，将 Loader 配置的对应小节设为：

```ini
[Logging]
Verbose = true
```

配置文件由 Loader 的插件 GUID 生成：
`BepInEx/config/oc2.oc2diylevelruntimewloader.cfg`。保留文件内其他配置。
重新启动游戏后采集双方 **从启动到复现之后** 的 `BepInEx/LogOutput.log`。

也可在启动游戏的进程环境中设置 `OC2_STUB_VERBOSE=1`。
只需要老鼠选择与交互探针时，可改用 `OC2_RAT_DIAGNOSTICS=1`。
环境变量必须传给实际游戏进程；单独设置后经已经运行的 Steam 启动，可能不继承。

`[BackpackNet]` 初始化、目录和存取确认日志常开；重复状态按键限频为五秒。
`[RatNet]` 交互探针启用后，每只鼠、每阶段最多每秒一条；附近选择采样有节流。
测试结束可关闭 Verbose。

## 老鼠验收

1. 主机和客机分别空手面对鼠，按使用/切菜键。记录双方看到的位置、命中时间。
2. 日志链应依次包含 `client-selected`、`selected/send-TriggerInteract`、
   `host-message`、`host-receive-TriggerInteract`、`hit-callback`。
   `rat id`、消息中的 `targetId` 必须指向同一只鼠。
3. 鼠携带食材时由客机击打：双方都应看到食材掉落、鼠逃回家；捡走掉落食材后，
   等鼠回家，食材不能再次消失。
4. 鼠出发后移动地面目标、拿走台面物品、把目标移远：鼠应扑空或放弃，不能远程挂嘴。
5. 同时放两只鼠并测试无目标巡逻、台面旁、缺地板边缘、重开关卡。

若有 `client-not-selected` 却无发送日志，优先看 `CliInteract`、`DynamicGrid`、
`colliders`、`canInteract` 和距离。若发出但主机无对应回调，比较实体 ID 和双方
`[Net] 实体扫描结果` 指纹。主机有 `hit-callback` 但客机仍不逃，检查位置同步组件。
客机缺 `SrvInteract` 属角色差异，不单凭它判断失败。

## 背包验收

1. 双方确认 `directory handshake ready=True`（大小写以实际日志为准），比较目录 hash、
   `IDs` 中 page/local-ID→prefab 映射，以及 `[Net]` 实体指纹。
2. 同一种食材按原料→半切→切后顺序存入，再反向顺序重复。主机、客机交替取出。
3. 半切取出继续切菜，进度应保留；切后取出可放台面、地面、投掷、交给另一厨师。
   检查双方手槽与物品形态一致，数量守恒。
4. 覆盖预摆食材、食材箱、随机箱、按钮生成器及初填；关闭库存 UI 后重复存取。
5. 覆盖空盘接队首、落水清空、取出后立即放回、退出再进、主客互换。
6. 单端缺协议模块/缺素材、目录不同应出现明确拒绝日志，不能销毁手中物或继续生成。

重点日志：`store confirmed`、`dispense confirmed`、`spawn role=... id=... prefab=...`、
`placement rejected`、`directory rejected`、`transfer locked`、`pending transfer resolved`。
报告卡手时，同时附具体食材、加工状态、哪端背包/哪端取出、最后一次操作时间。

## 检查结果与边界

- C#4/net35 主运行时与 LayoutEditor 独立编译通过；存在其他模块的既有编译警告。
- 协议模块 Release 编译通过，已 staging `BackpackProtocol.dll.bytes`。
- 背包托管行为 64 项断言与原生消息编解码 23 项检查通过，详见 WebBackpack/Checks~/README.md。
- 未完成 Unity 内 Harmony detour、实际实体扫描、AssetBundle 构建或双机网络测试。
- 每背包最多 128 个精确 prefab，增加八个分页实体，占用原生场景总实体预算。
  缺来源、循环加工链、目录超限或依赖缺失会拒绝物理存取并打印原因。
- 无法证明来源的实物保留在手中，不用 UID/名字猜形态。熟食/成品菜支持不在本次范围。
- 老鼠地板射线仍沿用现有固定高度，多层或动态升降厨房需额外实机覆盖。
