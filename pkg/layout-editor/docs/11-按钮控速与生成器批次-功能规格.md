# 11 · 按钮控速与生成器批次（v3.10.0，2026-10-14）

> 两个按钮玩法功能：**步带/传送带按钮控速**（每按一次循环切一档速度）与
> **食材生成器按钮批次送出**（每按一次送一批 N 个，批次完成后冷却）。共用
> 「stub 轮询」触发通道与 `Design/Speed Logic` 烘焙根。运行时版本
> `CustomStub.StubVersion.Value = 3.10.0`，真机依赖包须 ≥ 3.10.0。

## 1. 用户确认的语义（需求拍板记录）

| 决策点 | 结论 |
|---|---|
| 控速模式 | 循环自定义速度列表（每按一次切下一档，尾档回卷；列表 2~8 档，负值=反向；第 1 档=初始速度） |
| 生成器启动 | 每按一次按钮送**一批**，不是永久循环 |
| 首个出菜时机 | 按下**立刻**出第 1 个，之后每隔「触发间隔」再出 1 个直到满每批数量 |
| 批内节奏 | 批内也等间隔（间隔 = 既有 `triggerTime` 字段，含义不变） |
| 冷却语义 | **批次完成后**才进入 N 秒冷却（默认 5s，可配）；**按下即置灰锁定**——批次进行中与冷却期间按钮保持置灰不可再按（挂起 SwitchReenable 自动复位，冷却结束经 ServerTriggerDisableScript 网络通道复位点亮，双端同步）；落点站被占时该个持续补位，冷却起点随之自然顺延 |
| 触发源范围 | 仅普通按钮 Switch（拉杆/压力板不支持） |

## 2. 编辑器操作流

1. **步带/传送带**：右键参数面板 →「按钮控速」→ 勾选启用 → 编辑速度档位
   （✕ 删档 / + 添加档位）。未启用控速的步带不出现在联动目标下拉。
2. **食材生成器**：右键参数面板 →「按钮触发」→ 勾选「按钮触发批次送出」→
   设每批数量（1~50）与完成后冷却秒数。「开局触发」随之禁用（互斥：按钮
   模式下开局不再自动送出）。
3. **绑定按钮**：选中开关 → 触发编排①直连区（或开关右键「联动」Tab）→
   目标下拉选上述目标 → 添加。触发消息自动置空（stub 轮询通道无触发名语义，
   混合机器目标时机器原生触发名不受影响）。
4. 写回 → 导出（依赖包 ≥ 3.10.0）。

## 3. 关键架构决策（与既有铁律的关系）

| 决策 | 理由 |
|---|---|
| **Design/Speed Logic 独立 helper 根**（`SpdCtl_<hash8(itemId)>` / `SpnB_<hash8(itemId)>`），组件+tag 都挂 helper，目标伪根零占用 | `SetCustomStubTag` 整串覆写 =「一个物体一个 stub tag」铁律；步带伪根已有 `TravelatorReverse\|`、传送带有 `ConveyorDirectionSync\|`，挤占必互踩。独立根同时防 `ButtonLinkBakery.CleanupStale` 误删（CoaxialButtonBakery 同款原因） |
| **按钮/目标一律场景路径引用**（`GameObject.Find("A/B")` 天然唯一） | 免改名：改名会破坏 BLRelay 的 `N:` 段记录与 `new:` 物品的 hierarchyPath 兜底匹配；路径含 `/` 不与 tag 转义集（`%,;>\|`）冲突 |
| **stub 轮询通道**：轮询按钮子树 `TriggerDisableScript.m_script.enabled` 下降沿（SwitchReenable/Coaxial 同款），不走 vanilla `objectToTrigger` | vanilla `GameObjectUtils.SendTrigger` 只达 `ITriggerReceiver`，stub 组件收不到（仓库铁律）。控速按钮**保留**默认 `SwitchReenable\|0.35` 自动复位（可反复按）；**批次按钮**按下置灰后由 ButtonSpawnerBatch 挂起其 SwitchReenable 直到冷却结束才复位点亮 |
| **原生 TriggerTimer 停用放运行时组件内**（绑定 spawner child 时反射写 `m_startTiming=false / m_startTrigger="" / m_triggerAtStart=false`），不在写回烘焙 | 写回主路径 `ReloadPseudoAssetsFull` 会整体重建 child（override 必丢）；且编辑器 Play 与真机自愈两条加载路径都在 `ServerTriggerTimer.StartSynchronising`（握手后才 arm）之前完成停用，时序安全 |
| **批次生成仅服务端驱动**（`GameApi.IsServerMachine()`），逐个 `SendTrigger(m_trigger)` 复用原生链 | 生成经 `ServerTriggerAttachedSpawn.OnTrigger` → `NetworkUtils.ServerSpawnPrefab` 联网呈现；站空闲守卫（`m_attachStation.HasItem()` + `IConveyenceReceiver.IsReceiving()`）镜像原生 `OnTrigger`，忙则补位不硬塞。运行时组件等待 `IsSynchronisationActive()` 后才绑 Server 同步器（时序铁律） |

## 4. 数据通道

### 4.1 DTO（`LayoutEditorModels.cs` ↔ `types.ts` 镜像）

```
LayoutSpeedControlDto { enabled, levels: float[] }        // 2~8 档，非 0
  ├─ LayoutTravelatorStubDto.speedControl
  └─ LayoutConveyorStubDto.speedControl
LayoutFoodSpawnerStubDto { startByButton, batchCount(1~50), buttonCooldown(≥0) }
                                                            // triggerTime 复用为批内间隔
```

- 写回校验 `ValidateSpeedControlConfigs`（HttpServer 三处接入：`/api/scene/layout`
  / `oc2_validate_scene` / `oc2_commit_scene`）：档位 ≥2 且全非 0 违规 400；批次
  参数越界归一。前端 `serialize.ts` 同款归一 + 防污染（speedControl 仅许出现在
  对应 stubKind 上）。
- 触发源不另设文档字段——复用 `switchLinks`（targetId = 目标 item，trigger 留空）。

### 4.2 tag 载体（helper 上单用途，整串覆写；`%,;>|` 转 %XX）

```
SpeedCtl|E:<1|0>|T:<目标路径>|N:<按钮路径,..>|L:<s1,s2,..>
SpawnerBatch|E:<1|0>|T:<目标路径>|N:<按钮路径,..>|C:<count>|I:<interval>|D:<cooldown>
```

浮点 invariant。解析端 `EntryPoint.HealButtonSpeedControl/HealButtonSpawnerBatch`
（段式 KV，与 Coaxial 对称）。

### 4.3 组件（`Assets/WebCustomStubRuntime/Switch/`）

```
ButtonSpeedControl { m_enabled, m_targetPath, m_buttonPaths[], m_speeds[] }
ButtonSpawnerBatch { m_enabled, m_targetPath, m_buttonPaths[], m_count,
                     m_intervalSeconds, m_cooldownSeconds }
```

均为自愈类（AddComponent→enabled=false→配置→enabled=true 防竞态；无 ticker
无补丁；HealScene 计激活票）。

### 4.4 特征映射（stub_levels.txt，四处同步齐备）

| tag | 组件 | 特征 |
|---|---|---|
| `SpeedCtl\|` | ButtonSpeedControl | `speedctl` |
| `SpawnerBatch\|` | ButtonSpawnerBatch | `spawnerbatch` |

旧运行时遇新 tag 前缀自然跳过（`IsStubTag` 门控），零破坏；用新功能的关卡
需 ≥ 3.10.0 重导出。

## 5. 运行时行为

### 5.1 ButtonSpeedControl

- 绑定：`m_targetPath` 伪根子树优先找 Travelator，否则 ConveyorStation；按钮
  逐个 `GameObject.Find` + 子树扫 `TriggerDisableScript`（20s 未就绪降 1s 轮询）。
- 启动压第 0 档（与烘焙侧 `ApplyStub` 写入的 `speed=levels[0]` 一致，防 heal
  路径原生字段被还原）。
- 按压 → `index=(index+1)%len` → 应用：
  - Travelator：`m_speed` + 反射私有 `SetSpeedOnMaterial()`（皮带材质 `_speed`
    必须与推人速度一致；`Start()` 只调一次，运行时改速必须补调）；
  - ConveyorStation：`m_conveySpeed`（`ServerConveyorStation.RefreshStartConveying`
    每次投递开始读 `1/速度` 为时长——改写对在途投递零影响）。
- 联机：按压禁用状态由 vanilla 网络广播呈现到各端，组件每端各跑一份各自
  应用——同配置同按压序列结果天然一致（TravelatorReverser 同款论证），无需
  自定义消息。
- 与定时反转可共存（反转只动 localRotation、控速只动 m_speed/材质，互不干扰）。

### 5.2 ButtonSpawnerBatch 状态机

```
空闲 Idle ──按钮下降沿──▶ 批次中 Delivering（按钮置灰锁定：挂起 SwitchReenable）
批次中：第 k 个（0 起）计划时刻 = 批次开始 + k×间隔；到点且落点站空闲
  → SendTrigger(m_trigger)（m_trigger 从 TriggerAttachedSpawn 实例读，不硬编码）；
  站忙 → 持续补位；期间按钮置灰不可按。
第 N 个实际生成完毕 ──▶ 冷却 Cooldown（起算 = 最后一个生成时刻；按钮保持置灰）
冷却：m_cooldownSeconds 后回 Idle——解除 SwitchReenable 挂起并经
  ServerTriggerDisableScript 网络通道补发复位触发，按钮点亮可按下一批。
```

- 客户端组件空转（绑定 spawner 后即退出主循环）——生成走服务端网络链。
- 落点站守卫反射失败时按空闲放行（原生 `OnTrigger` 内部守卫兜底，最多多送
  绝不相卡）。

### 5.3 写回 / 回导链路

```
写回：SceneLayoutApplier（only==null||"items"）→ SpeedControlBakery.Sync
      → 解析目标（createdObjects 优先）+ switchLinks 收集触发源
      → EnsureHelper + 反射挂组件 + 写 tag
      → CleanupStale（仅全量写回；items 作用域不清）
      + LayoutEditorStubIO.ApplyStub：speedControl 启用时 stub.speed=levels[0]
回导：SceneLayoutExporter → SpeedControlBakery.AttachExportData（items 填
      speedControl/startByButton）+ ImportSwitchLinks（合并进 switchLinks；
      同 (开关,目标) 对以 stub 条目为准去重——objectToTrigger 残留的 vanilla
      "Switch" 条目让位）
```

- `ApplySwitchLinks` 未排除 stub 目标（objectToTrigger 残留无害：伪根转发到
  child 后无 `ITriggerReceiver` 响应 "Switch" 名；回导侧已去重）。
- helper 解析失败保留既有不删（CleanupStale 误删防护，Coaxial 同款）。

## 8. 已知边界

- 批次中途无停止语义（站被堵死则批次停滞、冷却不开始，按压持续无效——
  「批次没完成不进冷却」的既定语义）。
- 拉杆（ToggleSwitch 双态）与压力板不做触发源（语义不明确，未实现）。
- 生成器目标若无落点 AttachStation（`ServerTriggerAttachedSpawn.FindAttachStation`
  返回 null），原生生成永不发生——批次会一直等站空闲，属原生机制约束。

## 10. 批次按钮置灰锁定（2026-10-15 需求变更）

- 语义：批次按钮**按下即置灰**，批次进行中 + 冷却 N 秒全程不可再按，冷却
  结束自动点亮。（原实现按钮 0.35s 自动回绿、按压仅被状态机忽略。）
- 实现：`SwitchReenable` 新增 `m_suspended` 闸门（挂起时按压不自动复位）；
  `ButtonSpawnerBatch` 绑定按钮时抓取其 SwitchReenable 与
  `TriggerDisableScript.m_enableTrigger`，批次开始挂起全部触发按钮、冷却
  结束解除挂起并经 ServerTriggerDisableScript 网络通道补发复位（双端同步；
  CannonGuard 同款，不直写 Interactable.enabled）；组件中途禁用/销毁时
  OnDisable 兜底解锁防按钮永久置灰。烘焙侧不变（SwitchReenable|0.35 仍烤，
  运行时挂起）。
- 边界：批次中途停滞（落点站堵死）则按钮一直置灰——与「批次没完成不进
  冷却」既定语义一致；控速按钮不受此变更影响（仍可反复按）。
