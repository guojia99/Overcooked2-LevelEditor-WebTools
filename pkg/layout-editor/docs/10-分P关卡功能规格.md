# 10 · 分 P（换 P）关卡功能规格

> **文档性质**：产品需求 + 实现规格（供编辑器前后端、动画烘焙与关卡作者共用）。
> **术语**：本文统一写作 **「分 P」**；与社区口语 **「换 P」** 同义（指同一套「多阶段桌面/地形替换」机制）。
> **关联模块**：五层编辑（`layout-editor/docs/03` §6）、动画组（`AnimGroupBakery` / `animControls`）、写回全量策略（动画层）、`schemaVersion` 三处同步（架构技能 §横切铁律）。
> **状态**：v3 —— M1（数据与编辑）+ M2/M3 核心（slot 根写回结构、转场 Animator/时间轴链自动烘焙）已实现（2026-10-09）；决策记录见附录 A，海浪素材调研见附录 B。
>
> **实施映射**：编辑态 `web/src/editor/partLevel.ts`；序列化 `serialize.ts`（slot parentPath/partId 归一化/fx 触发联动）；持久化 `LayoutEditorPartLevelStore.cs`（part_level~ sidecar）；场景结构与烘焙 `PartTransitionBakery.cs`（slot 根 park + Idle/Entry/Exit controller + Design/PartTimeline 触发链 + TriggerKillAttachments 清理）；写回接线 `SceneLayoutApplier`（EnsureSlotRoots/Sync/防堆叠 part 键/行走面分流）。

## 1. 目标与玩法概念

### 1.1 玩家侧体验

分 P 表示：**同一张关卡在时间轴上自动切换多套「可玩布局」**（桌台、厨具、地形、装饰等），切换过程以 **演出动画** 呈现，玩家 **仍可移动**（不锁输入），本质是场景物件位移，而非切场景或读档。

典型节奏示例：

| 阶段 | 时长 | 说明 |
|------|------|------|
| 稳定期 | 如 60s | 当前 P 布局可正常游玩 |
| 转场期 | 如 5s | 旧 P 退场 + 新 P 入场（可拆：2s 旧布局退场、3s 新布局入场） |
| 线性推进 | P1 → P2 → … → PN 结束 | **运行时不做循环**（对齐决策 Q2）；需要循环体验的作者用「拷贝分 P」手动延长链（如 P1→P2→P3→P1′） |

### 1.2 设计边界

- **不仅是「换几个关键道具」**：某一 P 可以整块替换上一 P 的 **玩法层内容**（核心层 + 地板层等），甚至以 **地形/地板** 变化为主、桌台变化为辅。
- **与现有「五层编辑」正交**：分 P 是在「单层关卡文档」之上增加的 **阶段维度**；每个 P 内部仍按装饰 / 核心 / 地板 / 背景（及动画编排）组织，规则与现编辑器一致。
- **运行时实现边界（强制）**：分 P 只使用 Unity 原版关卡已有的能力——`Animator` + `TriggerQueue` / `TriggerTimer` / `TriggerOnAnimator`、物体位移动画、`TriggerKillAttachments`。**唯一确认的新增运行时行为**是 `CustomStub.PartSlotGuard`（离场保护，见 §4.6；对齐决策 Q3）；除此之外不新增 CustomStub、不新增 C# 运行时渲染补丁。
- **原版先例背书**：原版 DLC 存在大量同构「舞台动画」——`campsite_special`（DLC05）的 `section_01~04` + `arttransitions_{section}_{intro,transition,end}`、`beach_special`（DLC02）的 `layout_02/03/04`、`beach_1_2` 的 `set_01/02/03_{down,up}`（与 sink_then_rise 同构）等共 231 个 stageanimations 对象（附录 B）。

## 2. 编辑器模式与不可逆约定

### 2.1 进入分 P 模式

1. 作者在布局页顶部 **显式开启「分 P 关卡」**（`partLevel.enabled = true`），首次开启弹出向导：确认 P 数量、默认转场 preset、存量物件迁移。
2. **存量迁移（决策 D9）**：开启时现有全部物件 **默认归 base 层**（含装饰/核心/地板/背景），作者随后手动把玩法内容分进各 P；向导提供按层勾选的一键分流。
3. 开启后 UI 进入 **分 P 编排态**：增加 **基础层 / P1…PN** 切换、对比叠显、分 P 时间轴与转场配置入口。
4. **不可逆（前后端双守卫）**：一旦保存为分 P 关卡，前端不提供关闭开关；后端 Apply 对 `enabled:true` 的文档拒绝清空 `parts` 或降级请求。若需回退，通过写回历史或副本关卡操作。

### 2.2 与普通关卡的兼容

| 状态 | `partLevel` | 行为 |
|------|-------------|------|
| 普通关卡 | 缺省或 `enabled: false` | 与现逻辑完全一致；物件无 `partId` 概念（不展示 P 选项卡） |
| 分 P 关卡 | `enabled: true` | 必须定义 `parts[]`（≥2 个才有意义，1 个警告）；转场、清理策略可配 |

**P1 语义（决策 D1 修订）**：P1 是 **0 秒即存在** 的首套布局，玩家开局视觉与普关一致；但 **场景结构上 P1 与 P2…PN 同构**——都住各自的 slot 根 `Design/PartSlots/<pid>/`，P1 初始 parked 偏移为 0。首次开启分 P 时把存量物件一次性迁入 `Design/PartSlots/p1/`（u: instanceId 不变、匹配不断链），迁移本身即一次全量写回。

**P2…PN 常激活停放（决策 F5 修订）**：P2…PN **不使用 SetActive(false)**（Unity Animator 不驱动 inactive 层级；游戏 Server 组件不注册、后期启用无原版机制保障）。所有 slot 根 **常激活 + 停放在 park 偏移处**（默认 y−30m），转场动画驱动根位移。原版移动岛关卡即此模式。

## 3. 内容分层模型

分 P 模式下，作者在 **两个维度** 上编辑：

1. **纵向（现有）**：装饰 / 核心 / 地板 / 背景 / 动画编排 —— 与 `S.currentLayer` 一致。
2. **横向（新增）**：**基础层（base）** 与 **P1…PN**（`S.currentPart`）。

### 3.1 基础层（`base`）

- **含义**：全程不变、不参与 P 替换的「主场景壳」——远景、固定装饰岛、不参与玩法轮换的地板/背景等。
- **容量**：完整四子层（装饰 + 核心 + 地板 + 背景）。
- **硬性要求（决策 D8）**：base 层 **必须包含至少一块静态地板**（校验器硬失败）——出生/重生锚点（`ObjectContainer` 首静态 Col_Floor 机制）必须落在不被替换的地板上；否则转场期死亡重生会锚在被替换的 P 地板上。
- **编辑隔离**：选中基础层时，画布不得显示任一 P 层物件（含 P1）；选中某 P 时不显示其他 P 与 base（可开叠显，见 §3.4）。
- **写回**：base 物件写回现路径（`Design/Counters`、`Art/Ground` 等），不挂 slot 根。

### 3.2 P 层（`p1` … `pN`）

| 层 | 角色 | 场景结构 |
| --- | --- | --- |
| **P1** | 开局布局 | `Design/PartSlots/p1/`，parked 偏移 = 0 |
| **P2…PN** | 替换段 | `Design/PartSlots/<pid>/`，parked 于 `parts[].park` 偏移处 |

每个 slot 根内部子结构（决策 D1/D3）：

```
Design/PartSlots/<pid>/
├── Counters/…          # 物件按 tier 归子目录（同现 defaultParent 规则）
├── Ground/…            # 地板 Plane + 各自 Col_Floor 子碰撞体（随根移动）
└── AnimGroups/<组名>/   # P 内循环动画组根（groupHierarchyPath 强制指到此处）
```

- 每个 P 层内部仍分装饰 / 核心 / 地板 / 背景；操作方式与现网一致。
- **严格作用域**：在 Pk 上操作不得改动 Pj（j≠k）或 base 数据；剪贴板、框选、动画组成员绑定均带 `partId` 校验。

### 3.3 「整块替换」的可替换范围（可配置）

- 默认可替换包 = 该 P 下 **核心层 + 地板层 + 装饰层** 中 `partScoped: true` 的物件及该 P 专属地板矩形。
- 物件级字段：
  - `partScoped`（P 层内新建物件默认 true；base 层物件 false）；
  - `survivesPartSwitch`（默认 false）：true 时该物件受 `PartSlotGuard` 离场保护（§4.6）。
- 背景层是否随 P 替换：每 P 可配 `replaceBackground`（默认 false）。
- `FloorObject` 同样携带 `partId`（决策 D10）；不新增 `partLayer` 字段（层数由现有 tier 推导，已删除原案）。

### 3.4 对比 / 叠显（仅编辑辅助）

编辑某 P 时可勾选：叠显 base（半透明、不可点选）、叠显任一其他 Pj。叠显为纯视图状态，不写入文档。

### 3.5 动画层与分 P 的关系

- **分 P 转场**：专用动画组 `animRole: "partTransition"`，**按 slot 根组织**（决策 D2）：每个 P 一个转场组，成员 = 该 slot 根（objectInstanceIds），组内两个事件状态——退场（0 → park）与入场（park → 0），各自绑定外部触发器。**不按 transition 组织**（lift/drop 的 Δy 是事件级统一值，且循环链下同一根会被两个转场驱动、成员 re-parent 冲突）。
- **P 内循环动画**（传送带、灯笼等）：仍用现有动画组；带 `partId` 的组 `groupHierarchyPath` 强制写 `Design/PartSlots/<pid>/AnimGroups/<组名>`（决策 D3），组根随 slot 根移动。
- **全屏特效**：fx 组（shake/flash）用于转场期；参数沿用 `shakeAmplitude / flashIntensity / flashColor / soundCue`。

### 3.6 触发器命名（烘焙器生成，保留名冲突校验）

| 触发名 | 时机 | 载体 |
| --- | --- | --- |
| `PartSwitch_<from>_<to>` | 转场开始（广播） | `Design/PartTimeline/` 上 TriggerTimer 链 |
| `PartSwitch_<from>_<to>_in` | 新 P 入场（out/in 分拍时） | 同上（inDelay timer） |
| `Stable_<pid>` | 新 P 就绪（转场全部完成） | 转场组 endTrigger 链 |
| `Kill_<from>` | 清理时刻（Stable 后延迟 cleanupDelaySeconds） | cleanup timer |

与 `BLGo_*` / `BLD_*` / `Start` / `BLPress` 等保留名冲突校验加入写回校验器。

## 4. 运行时：切换、清理与时间轴

### 4.1 时间轴（线性，无循环）

- 每个 `transition` 携带 `stableSeconds`（**fromPart 的稳定时长，唯一权威**，决策 D4）；`parts[]` 不存时长。
- 时间轴由烘焙器生成于 `Design/PartTimeline/`：一串原版 `TriggerTimer`（首个 `m_startTiming=true` 回合开始自动计时，后续由 `Stable_*` 触发装填）+ `TriggerOnAnimator` 转发 + `TriggerKillAttachments` 载体。**不写任何新 C# 组件**。
- 循环需求 = 拷贝分 P（§4.7）。

### 4.2 转场节奏 preset（方向与节奏解耦，决策 Q1）

**方向**由每个 P 的 `park: { axis, offset }`（默认 down/30m）决定；退场恒 0→park、入场恒 park→0，**绝对无漂移**。preset 只定义 **节奏与演出**：

| ID | 名称 | 节奏行为 |
| -- | ---- | -------- |
| `sink_then_rise` | 下沉再上浮 | 先后：旧 P 退场 outSeconds 完成后，新 P 开始入场 inSeconds |
| `slide_cross` | 平移接力 | 并行：退场与入场同时开始，各动各的 park 轴 |
| `wave_wipe` | 海浪拍击 | slide 节奏 + 预置海浪物件包 + fx（附录 B：素材已确认存在） |

约束：某 P 的入场方向 = 自身 park 反向。牺牲「同一转场中新 P 入场方向与旧 P 退出轴严格对称」的可配性，换取循环拷贝与多次转场的位置确定性。

### 4.3 转场特效

复用 fx 组：`shake`（相机 rig）、`flash`（`Lights/FX_Lightning` + `soundCue`）。海浪场景建议 `soundCue: "dlc_02_tidein_01"` / `"overcooked_2_dlc_07_wave_incoming"` 等原版 AudioTrigger（附录 B）。

### 4.4 附着物与内容物清理（时序对齐决策 D6）

**清理时机 = 转场结束、新 P 稳定后**（`Stable_<to>` 延迟 `cleanupDelaySeconds` 秒执行）：

1. **slot 根清理**：每个 slot 根挂原版 `TriggerKillAttachments`（`m_trigger = Kill_<pid>`，killMode=Loose|Attached）——杀掉该 P 子树内全部 loose `IAttachment`（散落食材）与 `ServerAttachStation` 上的物品（盘上菜、锅内物；锅具即 AttachStation 派生，无独立事件名，原决策 D7 并入此处）。
2. **全场散落物大扫除**：`Design/` 根挂第二份 `TriggerKillAttachments`（Loose-only，`killLooseEverywhere` 默认 true）——清掉带出 P 范围的掉落食材（含 base 层散落物；spawner 随后自然补货）。
3. **玩家手持物保留**：手持物在 Chefs 子树且为 attached，两种模式都杀不到（原版行为，决策 D6b）。**无杀手持机制，也不新增**。

### 4.5 内容物清理开关

`cleanupContents`（默认 true）+ `cleanupDelaySeconds`（默认 0）。原案的 `destroyPartContentsOnExit` **删除**（决策 Q2）：布局实例永不销毁、只 parked 隐藏，拷贝式循环天然无垃圾。原案的 `respawnCarriedAttachments` **删除**：spawner 补货依赖原版行为，M4 实测确认（风险 R3）。

### 4.6 离场保护（唯一新增 CustomStub，决策 Q3）

`CustomStub.PartSlotGuard`（挂每个 slot 根）+ tag 载体 `PartExit|`（tag 前缀表三处同步：SetExporter.CustomStubTagPrefixes ↔ EntryPoint.HealObject ↔ loader HealScene）：

- 触发 `PartSwitch_<k>_<k+1>` 时，扫描 slot 子树：**已位移超过阈值**（如 1.5m，可推动的锅被玩家推走）或 `survivesPartSwitch: true` 的物件，按 **世界位姿不变** 改挂到常驻根 `Design/PartExits/<pid>/`。
- 不销毁、不重建，仅 Transform.SetParent（Server 组件与网络同步实体不断链）。
- **分 P 关卡自此依赖 CustomStub（Stub DLL）**——导出链路已有该机制（随机食材箱同款），不新增打包步骤。

### 4.7 拷贝分 P（手动循环）

web 提供「拷贝某 P」操作：复制该 P 的 items/floors/动画组为**新 part**（全新 instanceId `new:` 序列、新 slot 根、新 park），自动衔接转场。用于 P1→P2→P3→P1′ 的循环体验与「同布局微调复用」。

## 5. 结构化 JSON 设计（定案）

> 同步点：`LayoutEditorModels.cs` ↔ `web/src/types.ts` ↔ `serialize.ts` ↔ `schemaVersion`（三处镜像）↔ MCP 文档。

### 5.1 顶层字段（schemaVersion = 9）

```jsonc
{
  "schemaVersion": 9,
  "partLevel": {
    "enabled": true,
    "parts": [
      { "id": "p1", "label": "开局", "park": { "axis": "down", "offset": 30 }, "replaceBackground": false },
      { "id": "p2", "label": "一分钟后", "park": { "axis": "down", "offset": 30 } },
      { "id": "p3", "label": "再一分" }
    ],
    "transitions": [
      {
        "id": "t_p1_p2",
        "fromPartId": "p1", "toPartId": "p2",
        "kind": "partTransition",
        "preset": "slide_cross",
        "stableSeconds": 60,
        "totalSeconds": 5, "outSeconds": 2, "inSeconds": 3,
        "fxGroupId": "fx_thunder_p1_p2",
        "cleanupContents": true, "cleanupDelaySeconds": 0,
        "killLooseEverywhere": true
      }
    ]
  }
}
```

- `parts[]` 只存属性（id/label/park/replaceBackground）；时长唯一权威在 `transitions[].stableSeconds`。
- 转场链为 **线性 N−1 段**（pk → pk+1），校验器保证连贯。
- 原 `loop` / `defaultTransitionPreset` 字段保留可选（defaultTransitionPreset 仅作向导默认值）。

### 5.2 物件归属

```jsonc
// LayoutItem / FloorObject 扩展
{
  "instanceId": "new:…",
  "partId": "p2",              // 分 P 文档必填："base" | "p1"…（写回时前端强制补全）
  "partScoped": true,          // 默认：P 层内新建 true，base 层 false
  "survivesPartSwitch": false
}
```

- 普关兼容：无 `partLevel` 时忽略 `partId`（缺省按现行为）。
- 已删除原案 `partLayer` 字段（决策 D10）。

### 5.3 动画组区分

```jsonc
{
  "id": "ag_p2_slot",
  "displayName": "P2 槽位转场",
  "groupKind": "members",
  "animRole": "partTransition",   // 缺省 = gameplay
  "partId": "p2",
  "groupHierarchyPath": "Design/PartTransitions/p2",
  "triggerMode": "auto",          // 转场组由外部触发链驱动（PartSwitch_*）
  "startTrigger": "PartSwitch_p1_p2"
}
```

| `animRole` | 说明 |
| --- | --- |
| 缺省 / `gameplay` | 现有关卡动画（按钮、自动循环等） |
| `partTransition` | 分 P 槽位转场组；烘焙产物挂 `Design/PartTransitions/`；**按 slot 组织**（成员=slot 根），禁与 buttonLinks 绑定 |
| `partStable` | 可选：某 P 稳定期内的环境动画（预留） |

- 普通动画组带 `partId` 时组根强制迁入 `Design/PartSlots/<pid>/AnimGroups/`。
- 触发器命名遵守 §3.6；禁止与 buttonLinks/buttonEvents/Coaxial 混用同名 Trigger。

### 5.4 场景结构（定案）

```
Design/
├── PartSlots/{p1..pN}/{Counters,Ground,AnimGroups}/   # slot 根，常激活，park 偏移
├── PartTransitions/                                    # 转场组根（每 P 一组）
├── PartTimeline/                                       # 烘焙生成：TriggerTimer 链 + 转发 + Kill 载体
├── PartExits/{p1..pN}/                                 # PartSlotGuard 离场保护目标（常驻）
└── …（base 物件沿用现路径）
```

- `Design/Collision` 只放 base 静态 Col_Floor；Pk 地板的 Col_Floor 挂 slot 根下（仿 `CreateColFloorOnItem` 成员子挂模式），随根移动。
- `SyncWalkableToFloors` 按 partId 分流（M2）。
- 烘焙输出与现 `AnimGroupBakery` 产物同构（`TriggerQueue`、`AnimationFinished` 门控）；`animRole/partId` 写入嵌入 AnimGroupSource JSON，`AnimGroupImporter` 回读分流（JsonUtility 新字段前向兼容，旧档缺省 = gameplay）。

## 6. 编辑器 UX 需求摘要

1. **入口**：布局页顶部「分 P 关卡」开关 + 首次向导（P 数量、默认转场、存量迁移按层勾选，默认全归 base）。
2. **主导航**：基础层 | P1 | P2 | … | PN（先选 P，再选装饰/核心/地板/背景五层）。
3. **时间轴面板**（第二迭代）：稳定期 + 转场缩略图，拖拽调时长。
4. **转场向导**：选 preset（sink/slide/wave）自动生成转场组 + 时间轴链 + fx 组 + KillAttachments；wave 预置海浪物件包。
5. **校验器**：
   - 分 P 至少 2 个 P（1 个警告）；转场 from/to 连贯（线性 N−1 段）；
   - base 层必须含静态地板（硬失败，决策 D8）；可替换区覆盖全部可行走区（警告）；
   - 动画组成员 partId 与所属 P 一致；`PartSwitch_/Stable_/Kill_` 触发名与保留名冲突；
   - P2+ 根路径不与 P1 冲突；`parts[].park` 合法（axis ∈ down/up/left/right，offset 5~200）。
6. **写回策略（决策 D5）**：
   - 分 P 关卡的文档 items/floors **始终全量携带**（所有 P 所有层）；
   - 后端删除/更新/防堆叠 **按 partId 分桶**——文档出现的 part 桶内未匹配才删，未提及的 part 整体跳过；
   - `only=items|decor|floors` 语义变为「只允许改动对应层×part 的条目」；
   - 改 `partLevel` 元数据或转场动画 → 全量写回（与 animControls 同策略）。

## 9. 验收场景（测试计划）

1. **普关回归**：无 `partLevel` 的关卡打开、写回、导出、Play 与现网一致。
2. **二分 P**：P1 桌台 A、P2 桌台 B；60s 后 slide_cross 5s；玩家全程可移动；切换后 A 不可交互（parked 物理不可达）。
3. **仅地形**：P1/P2 核心桌台相同、地板形状不同；sink_then_rise；行走面（slot 内 Col_Floor）随根同步。
4. **闪电转场**：fx flash + shake，`soundCue` 可闻。
5. **手动循环**：P1→P2→P3→P1′（拷贝分 P）线性推进，无累积垃圾物件、无位置漂移。
6. **附着物**：玩家手持物转场后 **保留**；带出 P 范围的 loose 掉落物由大扫除清理；盘上菜/锅内物在 Stable+delay 后清理；可推动锅被推离原位后不随 slot 下沉（PartSlotGuard）。
7. **基础层**：全程可见的远景/装饰在任意 P 不闪烁、不被销毁；出生/重生锚点在 base 静态地板。
8. **存量迁移**：普关开启分 P（全归 base）→ 分流物件进 P1/P2 → 写回 → 重开文档一致；不可逆守卫生效（前端无关闭开关、后端拒绝降级）。
9. **parked 观察项**：P2 parked 期间其内自动生成器（AttachingFoodSpawner 类）行为观察（风险 R1）。
