# 10 · 分 P（换 P）关卡功能规格

> **文档性质**：产品需求 + 实现提示词（供编辑器前后端、动画烘焙与关卡作者共用）。  
> **术语**：本文统一写作 **「分 P」**；与社区口语 **「换 P」** 同义（指同一套「多阶段桌面/地形替换」机制）。  
> **关联模块**：五层编辑（`layout-editor/docs/03` §6）、动画组（`AnimGroupBakery` / `animControls`）、写回全量策略（动画层）、`schemaVersion` 三处同步（架构技能 §横切铁律）。

---

## 1. 目标与玩法概念

### 1.1 玩家侧体验

分 P 表示：**同一张关卡在时间轴上自动切换多套「可玩布局」**（桌台、厨具、地形、装饰等），切换过程以 **演出动画** 呈现，玩家 **仍可移动**（不锁输入），本质是场景物件位移/显隐/销毁与再生成，而非切场景或读档。

典型节奏示例：

| 阶段 | 时长 | 说明 |
|------|------|------|
| 稳定期 | 如 60s | 当前 P 布局可正常游玩 |
| 转场期 | 如 5s | 旧 P 退场 + 新 P 入场（可拆：2s 旧布局消失、3s 新布局出现） |
| 循环 | 可选 | P1 → P2 → … → PN → P1 … |

### 1.2 设计边界

- **不仅是「换几个关键道具」**：某一 P 可以整块替换上一 P 的 **玩法层内容**（核心层 + 地板层等），甚至以 **地形/地板** 变化为主、桌台变化为辅。
- **与现有「五层编辑」正交**：分 P 是在「单层关卡文档」之上增加的 **阶段维度**；每个 P 内部仍按装饰 / 核心 / 地板 / 背景（及动画编排）组织，规则与现编辑器一致。
- **运行时实现边界（强制）**：分 P **只使用 Unity 原版关卡已有的能力**——`Animator` + `TriggerQueue` / `TriggerTimer`、物体位移动画、显隐、Trigger Kill Attachment、向锅具/附着物发信号使其消失等。**不新增 CustomStub、不新增 C# 运行时渲染补丁**（与 v0.10「智能换 P」方向一致：结构化数据驱动既有烘焙链）。

## 2. 编辑器模式与不可逆约定

### 2.1 进入分 P 模式

1. 作者在关卡元数据或布局文档上 **显式开启「分 P 关卡」**（`partLevel.enabled = true`）。
2. 开启后 UI 进入 **分 P 编排态**：与普关相比，增加 **基础层 / P1…PN** 切换、对比叠显、分 P 时间轴与转场配置入口。
3. **不可逆**：一旦保存为分 P 关卡，**不允许再降级为普通单阶段关卡**（避免文档与场景中残留多份互斥布局导致写回/导出歧义）。若需回退，应通过写回历史或副本关卡操作，而非开关回关。

### 2.2 与普通关卡的兼容

| 状态 | `partLevel` | 行为 |
|------|-------------|------|
| 普通关卡 | 缺省或 `enabled: false` | 与现逻辑完全一致；所有物件落在隐式 **P1**（不展示 P 选项卡） |
| 分 P 关卡 | `enabled: true` | 必须定义 `parts[]`（至少 P1）；转场、循环、清理策略可配 |

**P1 语义（重要）**：P1 是 **0 秒即存在** 的首套布局，与「从未分 P 的关卡」在玩家开局时一致。编辑器中 P1 内容 **默认写回进场景主层级**（与现写回路径相同）；P2…PN 在场景中 **默认不激活/不实例化**（或实例化在隔离根下并禁用），仅在对应阶段经烘焙动画切入。

## 3. 内容分层模型

分 P 模式下，作者在 **两个维度** 上编辑：

1. **纵向（现有）**：装饰 / 核心 / 地板 / 背景 / 动画编排 —— 与 `S.currentLayer` 一致。  
2. **横向（新增）**：**基础层（base）** 与 **P1…PN**。

### 3.1 基础层（`base`）

- **含义**：全程不变、不参与 P 替换的「主场景壳」——远景、固定装饰岛、不参与玩法轮换的地板/背景等。
- **容量**：可包含与现编辑器相同的 **完整四子层**（装饰 + 核心 + 地板 + 背景）；**不包含**分 P 专有的「另一套可替换玩法岛」（那些进 P 层）。
- **编辑隔离**：选中 **基础层** 时，画布 **不得显示** 任一 P 层物件（含 P1），避免误点、误绑动画成员。
- **写回**：基础层物件写回场景 **常驻根**（如 `Design/` 下与现规则一致的路径），且 **不** 挂到某一 P 的 Animated 根下。

### 3.2 P 层（`p1` … `pN`）

| 层 | 角色 | 与场景关系 |
|----|------|------------|
| **P1** | 开局布局 | 与普关一致：写回主玩法根；**画面上**编辑 P1 时也不应叠显「未选中 P」的幽灵体（除非作者打开对比，见下） |
| **P2…PN** | 替换段 | **整块替换** 上一活跃 P 的 **可替换范围**（见 §3.3）；非增量补丁 |

每个 P 层内部：

- 仍分装饰 / 核心 / 地板 / 背景；操作方式（吸附、调色板、右键 stub、分层写回按钮）与现网一致。
- **严格作用域**：在 Pk 上移动桌台，不得改动 Pj（j≠k）或基础层数据；剪贴板、框选、动画组成员绑定均带 `partId` 校验。

### 3.3 「整块替换」的可替换范围（可配置）

默认 **可替换包** 包含：该 P 下 **核心层 + 地板层 + 装饰层** 中标记为 `partScoped: true` 的物件，以及该 P 专属地板矩形。

建议在物件级增加：

- `partScoped`（默认 true 于 P 层内新建物件；基础层物件为 false）
- `survivesPartSwitch`（默认 false）：为 true 时 **不随 P 切换销毁**（如被玩家带到相机外的锅、特殊剧情道具）

**背景层**是否随 P 替换：每 P 可配置 `replaceBackground: boolean`（默认 false，仅换桌台/地形时保持天空/海面不变）。

### 3.4 对比 / 叠显（仅编辑辅助）

在编辑某一 P 时，作者可勾选：

- **叠显基础层**（半透明、不可点选）
- **叠显其他 P**（任选 Pj 作参考，半透明、不可点选）

叠显 **不得** 写入文档为额外物件；仅视图状态。

### 3.5 动画层与分 P 的关系

- **分 P 转场**：使用 **专用动画组类型**（见 §5），与机关按钮驱动的普通 `AnimGroup` 区分。
- **P 内循环动画**（传送带、灯笼等）：仍用现有 `animControls.groups`，但每个组应带 `partId`，写回/烘焙时仅绑定到对应 P 的活跃根。
- **全屏特效**（`groupKind: "fx"` 的 shake / flash）：可用于转场期；事件参数与现 `AnimGroupEvent` 一致（参考 OC1 Story **4-1** 闪电、抖动节奏）。

## 4. 运行时：切换、清理与循环

### 4.1 时间轴

文档级配置示例语义：

- `stableDurationSeconds`：本段 P 保持时长（稳定期）
- `transition`：转场定义（类型、时长、子阶段）
- `order`：P 顺序；`loop: true` 时末段结束后回到 P1

循环示例：3 个 P → `P1 → P2 → P3 → P1 → …`

### 4.2 转场动画类型（首批）

实现时映射到 **成员组位移动画**（lift / drop / move / rotate）+ 可选 **fx 组**（shake / flash）：

| ID | 名称 | 行为摘要 |
|----|------|----------|
| `sink_then_rise` | 下沉再接上浮 | 旧 P 整体下沉至视野外或地下；**结束后** 新 P 从下方（或默认方向）上浮到位 |
| `slide_cross` | 平移接力 | 旧 P 沿轴向（下/上/左/右可配）飘出；新 P **同时**从反方向接入 |
| `wave_wipe` | 海浪拍击 | 海浪/潮水特效带掩蔽：旧 P 被「拍掉」，新 P 在浪后生成（美术可用粒子 + 地板动画，仍走 Animator） |

各类型在 JSON 中 **必须** 声明 `kind: "partTransition"`，以便 `AnimGroupBakery` / 导入器不与普通机关动画混淆。

### 4.3 转场特效

- 复用现有 **fx 组**：`shake`（相机 rig）、`flash`（`Lights/FX_Lightning` + 可选 `soundCue`）。
- 鼓励参考 **OC1 Story 4-1** 的闪电、屏震节奏；参数沿用 `shakeAmplitude`、`flashIntensity`、`flashColor`、`soundCue`。

### 4.4 附着物与道具生命周期

转场前后常见需求：

1. **被玩家带到相机范围外的附着物/食材**：转场开始时 **销毁**（或 Kill Attachment）；新 P 稳定后按该 P 布局 **重新生成**（spawn 点、Dispenser、AttachingFoodSpawner 等现 stub 逻辑）。
2. **当前 P 范围内残留物**：切换完成后，默认 **销毁当前 P 全部 `partScoped` 物件上的动态内容**（盘上菜、锅内物等），**除非** `survivesPartSwitch` 或玩家已带出范围。

实现手段（运行时已有，不写 CustomStub）：

- Trigger **Kill Attachment**（与原版关卡一致）
- 向厨具/锅具发 **消失/清空信号**（与现有关卡编排相同事件名，由烘焙写入 TriggerQueue）

### 4.5 切换后销毁当前 P 内容（开关）

`destroyPartContentsOnExit: boolean`（**默认 true**）

- **true**：旧 P  deactivated 或销毁其根下 `partScoped` 静态布局实例（玩家已带出的除外），避免下一段 P 叠层穿帮。
- **false**：仅做位移动画隐藏，保留实例（特殊关卡慎用；需文档警告性能与状态污染）。

## 5. 结构化 JSON 设计（草案）

> 以下为 **布局文档扩展** 提示；落地时需同步：`LayoutEditorModels.cs` ↔ `web/src/types.ts` ↔ `serialize.ts` ↔ `schemaVersion` ↔ MCP 文档。

### 5.1 顶层字段

```json
{
  "schemaVersion": 7,
  "partLevel": {
    "enabled": true,
    "loop": true,
    "parts": [
      { "id": "p1", "label": "开局", "stableDurationSeconds": 0 },
      { "id": "p2", "label": "一分钟后", "stableDurationSeconds": 60 },
      { "id": "p3", "label": "再一分", "stableDurationSeconds": 60 }
    ],
    "transitions": [
      {
        "id": "t_p1_p2",
        "fromPartId": "p1",
        "toPartId": "p2",
        "kind": "partTransition",
        "preset": "slide_cross",
        "totalSeconds": 5,
        "phases": {
          "outSeconds": 2,
          "inSeconds": 3
        },
        "axis": "down",
        "fxGroupId": "fx_thunder_p1_p2",
        "destroyPartContentsOnExit": true,
        "respawnCarriedAttachments": true
      }
    ],
    "defaultTransitionPreset": "sink_then_rise"
  }
}
```

### 5.2 物件归属

在 `LayoutItem` / `FloorObject` 上扩展（示例）：

```json
{
  "instanceId": "new:…",
  "partId": "p2",
  "partLayer": "items",
  "partScoped": true,
  "survivesPartSwitch": false
}
```

- `partId: "base"` 或缺省且位于基础层编辑态 → 基础层。
- 普关兼容：无 `partLevel` 时忽略 `partId`。

### 5.3 动画组区分

在 `AnimGroup` 上扩展：

```json
{
  "id": "ag_p2_slide",
  "displayName": "P2 入场",
  "groupKind": "members",
  "animRole": "partTransition",
  "partTransitionId": "t_p1_p2",
  "partId": "p2",
  "triggerMode": "auto",
  "startTrigger": "PartSwitch_p1_p2"
}
```

约定：

| `animRole` | 说明 |
|------------|------|
| 缺省 / `gameplay` | 现有关卡动画（按钮、自动循环等） |
| `partTransition` | 仅服务分 P 转场；烘焙产物挂到统一 `Design/PartTransitions/` 根 |
| `partStable` | 可选：某 P 稳定期内的环境动画（与转场解耦） |

**禁止** 与普通 `buttonLinks` 混用同一 Trigger 名；分 P 触发器命名建议前缀 `PartSwitch_`。

### 5.4 Unity 兼容性

- 烘焙输出须与 **现 AnimGroupBakery 产物同构**（`Animated Objects` 根、`TriggerQueue`、`AnimationFinished` 门控）。
- 额外类型信息写入嵌入的 **AnimGroupSource** JSON（`animRole`、`partTransitionId`），供 `AnimGroupImporter` 回读时分流 UI。
- 场景内 P2…PN 推荐使用 **独立子根**（如 `Design/PartSlots/p2/`），转场动画整体移动该根；P1 与现 `Design` 布局一致以减少迁移成本。

## 6. 编辑器 UX 需求摘要

1. **入口**：关卡设置或布局页顶部「分 P 关卡」开关 + 首次向导（定义 N、默认转场）。
2. **主导航**：基础层 | P1 | P2 | … | PN（与五层 Tab 组合：先选 P，再选装饰/核心/地板/背景）。
3. **时间轴面板**（可选第二迭代）：展示稳定期 + 转场缩略图，拖拽调整时长。
4. **转场向导**：从预设选择 `sink_then_rise` / `slide_cross` / `wave_wipe`，自动创建成员组（整 P 根）+ 可选 fx 组。
5. **校验**：
   - 分 P 关卡至少 2 个 P 才有意义（否则警告）
   - 每个 `transition` 的 `from/to` 必须连贯
   - 动画组成员 `partId` 与当前编辑 P 一致
   - 写回前检查 P2…PN 根路径不与 P1 冲突
6. **写回策略**：
   - 改 P 内物件：可按现有分层 `only` 写回，但 **必须带 `partId` 过滤**
   - 改 `partLevel` 元数据或转场动画：**全量写回**（与 `animControls` 相同）

## 7. 工作范围与非目标

### 7.1 本期包含

- 布局文档模型、前端分 P 编辑态、对比叠显
- 写回：多 P 根、分 P 元数据、转场动画烘焙（复用 AnimGroupBakery）
- 导出：随场景 bundle 走，**不**因分 P 强制 CustomStub
- 玩家移动不锁定；输入与碰撞在转场期保持（仅视觉演出）

### 7.2 本期不包含

- 新 CustomStub / `WebCustomStubRuntime` 行为
- 自定义着色器、C# 运行时补丁、非 Animator 的补间系统
- 跨关卡 P 共享（每个关卡独立 `partLevel`）
- 联机不同步 P 索引的专门修复（默认沿用现有关卡同步假设）

## 8. 实现分期建议（供排期）

| 阶段 | 交付 |
|------|------|
| **M1 数据与编辑** | `partLevel` + `partId` 字段；基础层/P 切换与视图隔离；普关兼容 |
| **M2 写回与场景根** | P1 主根 + P2…PN 槽位根；分层写回过滤；导出无回归 |
| **M3 转场烘焙** | 三种 preset + fx；`animRole` 分流；嵌入 Source 回读 |
| **M4 清理与循环** | `destroyPartContentsOnExit`、附着物重生、循环时间轴 |
| **M5 文档与 MCP** | 用户指南章节、MCP 工具与 schema 同步 |

## 9. 验收场景（测试计划）

1. **普关回归**：无 `partLevel` 的关卡打开、写回、导出、Play 与现网一致。
2. **二分 P**：P1 桌台 A，P2 桌台 B；60s 后 `slide_cross` 5s；玩家全程可移动；切换后 A 不可交互且已隐藏/销毁。
3. **仅地形**：P1/P2 核心桌台相同，地板形状不同；`sink_then_rise`；行走面随地板写回同步。
4. **闪电转场**：接 fx flash + shake，音效 `soundCue` 可闻。
5. **循环**：P1→P2→P3→P1 两轮无累积垃圾物件（`destroyPartContentsOnExit: true`）。
6. **带出附着物**：玩家持物跑出相机；转场后物销毁；新 P 稳定后 spawner 恢复正常。
7. **基础层**：全程可见的远景/装饰在任意 P 不闪烁、不被销毁。

## 10. 给 AI / 开发者的执行提示词（精简版）

```
你在 OC2 关卡编辑器中实现「分 P 关卡」。

约束：
- 复用现有五层编辑与 AnimGroupBakery；扩展 LayoutDocument（partLevel、partId、animRole）。
- 分 P 转场必须是 animRole=partTransition 的结构化 JSON，烘焙结果与原生 TriggerQueue 兼容。
- 禁止为新功能添加 CustomStub 或运行时 C# 渲染补丁。
- partLevel.enabled 一旦为 true 则不可逆；P1=开局布局且写回主场景；P2..PN 为整段替换。
- 编辑基础层或某一 P 时默认隐藏其他 P（可选半透明对比）。
- 转场预设：sink_then_rise、slide_cross、wave_wipe；特效用现有 fx 组 shake/flash。
- 切换时可销毁旧 P 内容（可开关），Kill Attachment / 锅具信号；循环 P1..PN。
- 同步改 C# DTO、web types、schemaVersion、MCP 文档与写回过滤。

先读：layout-editor/docs/03（前端层）、02 §3.4（动画烘焙）、.opencode/skills/oc2-architecture/SKILL.md。
```
